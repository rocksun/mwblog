**软件供应商喜欢宣称统一系统**，它们充当任何给定编码任务、数据功能或更广泛工作流的所谓“单一管理平台”。智能体数据检索公司 **Infino** 暗示了这种氛围，承诺为所有智能体提供单一的检索层。

在这种情况下，单一检索层意味着一个统一的（这就是那个词）数据库系统，它让所有AI智能体能够从一个地方查询所有数据。

## 智能体改变了数据查询范式

周三，[Infino](https://infino.ai/) 正式推出了其智能体检索平台，并表示构建该平台是因为智能体改变了数据查询范式，它们的查询方式与人类不同。

Infino 首席执行官 [Ekechi Nwokah](https://www.linkedin.com/in/ekechi/) 告诉 *The New Stack*，智能体是“自网页浏览器以来最大的新数据消费者”，但他感叹它们仍然“在使用为不同时代构建的碎片化技术栈”，即用于 SQL 的[数据仓库](https://thenewstack.io/data-warehouses-and-customer-data-platforms-better-together/)、用于关键词的搜索引擎、用于[语义搜索](https://thenewstack.io/superlinked-democratizes-real-time-semantic-search/)的[向量数据库](https://thenewstack.io/how-to-master-vector-databases/)，以及用于保持它们同步的 [ETL](https://thenewstack.io/from-etl-to-autonomy-data-engineering-in-2026/) 管道。

“我们正在为智能体折叠这个技术栈，”Nwokah 说。“我们的方法是将数据以 Parquet 格式存放在对象存储中，并让智能体直接对其进行搜索、排序、过滤、连接、聚合和推理。其结果是所有智能体读取数据的单一副本。”

正如我们从数据库基础第一课所知，传统的数据存储一直是为人类或应用程序优化的，即编写一个查询、等待并读取结果。

“智能体的行为截然不同，”Nwokah 说。“它发出许多小问题来回答一个大问题，通常是同时进行的，并且它收到的每一个结果都会消耗上下文，并可能增加后续模型调用的成本和延迟。这是现有数据存储并未针对其进行优化的全新读者。”

> “智能体的行为截然不同。它发出许多小问题来回答一个大问题，通常是同时进行的，并且它收到的每一个结果都会消耗上下文，并可能增加后续模型调用的成本和延迟。”

Nwokah 解释说，[Grep](https://thenewstack.io/the-grep-command-in-linux/)（在纯文本中搜索特定关键词或模式的行匹配的命令行工具）返回匹配项，然后智能体继续阅读整个文件。此外，他指出向量数据库将返回少量的块，然后智能体通过附加查询再次询问。此外，数据仓库返回行，然后智能体自己将它们组合起来。

“Infino 是专为这种数据读取器动态设计的检索层。它直接在对象存储上为智能体提供一个结合了结构化和非结构化查询的接口：低成本、大规模的排序搜索、精确计数、连接、过滤和聚合，”Nwokah 澄清道。

在数据搜索的黄金岁月里，查询模式相对可预测。当人类或应用程序进行查询时，搜索在搜索数据库上运行。分析在仓库中运行。向量数据库启用了近似查询并解锁了一类新的用例，但它们并未从根本上改变这些查询模式。每个查询都在自己的系统上运行，拥有自己的数据副本、自己的摄取管道以及运行它的团队。

今天，这些操作仍然可以跨越数据库加搜索引擎、向量数据库和数据仓库。智能体必须调用每一个，然后花费额外的模型轮次来组合结果。Infino 的回答是将检索功能直接嵌入到 SQL 中，这样整个问题就可以用一个查询来表达。

## 更少的数据任务、更少的粘合代码、集中式策略管理

“对于开发者和数据团队来说，它消除了整个管道以及管理它们所需的时间，”Nwokah 热情地说。“这意味着更少的系统、更少的摄取路径、更少的 ETL 作业、更少需要保持对齐的模式、智能体工具列表中更少的客户端，以及用于组合其结果的更少粘合代码。这也意味着一个治理智能体的地方。”

他强调了其组织在这里的方法，并表示当智能体的数据存在于单一副本中时，开发者“可以集中强制执行严格的策略”，这意味着对谁可以读取什么、智能体可以看到哪些行和列以及记录什么进行治理。

“将此与跨 MCP 网关和 SaaS 工具管理智能体权限进行比较，”Nwokah 敦促道。

> “对于开发者和数据团队来说，它消除了整个管道以及管理它们所需的时间。”

根据 Infino 的说法，开发者可以输入一个用自然语言提出的英语问题，它就会变成一个在毫秒内完成的查询。Infino 已经澄清，重要部分并非 SQL 本身；而是关键词搜索、语义搜索、过滤、聚合和分组可以同时发生，而无需强迫智能体协调多个系统并在中间结果堆栈上进行推理。

作为在平台开发过程中发现的另一个挑战，Infino 指出，即使检索速度很快，它也发现智能体在检索循环中花费了大量时间，即努力制定查询、搜索、决定结果是否足够好、尝试其他方法、验证答案并重复。Infino 表示，它将有针对性的推理模型与检索引擎集成在一起，因此这些更简单的任务比使用前沿模型运行得更快、更便宜。

## 数据存储挑战：Apache Parquet

Infino 解决的另一个挑战是它如何存储数据。Infino 没有为搜索、向量和分析维护单独的副本，而是将单一副本保存在对象存储上的 [Apache Parquet](https://thenewstack.io/an-introduction-to-apache-parquet/)（一种面向列的存储格式）中。

“核心引擎是开源的，Apache-2.0，在 GitHub 上，我们将所有数据存储为有效的 Parquet 文件，搜索索引嵌入在 Parquet 页脚旁边，因此任何读取 Parquet 的工具都可以在有或没有 Infino 的情况下读取数据。Infino Cloud 是我们的托管服务，具有一些额外的专有功能，例如能够指向你现有的 Parquet 数据并使其可搜索，而无需自己构建任何基础设施，”Nwokah 补充道。

Infino 将索引存储在 Parquet 文件中以加速检索，而底层数据保持 Parquet 不变。Iceberg 和 Hudi 可以管理相同的表，Spark、DuckDB、仓库和其他 Parquet 读取器仍然可以读取它。因此，数据的一个副本可以满足智能体需要查询它的不同方式。

Infino 还希望从数据到查询的路径比传统数据存储更简单。该公司认为，设置集群、节点、分片和人员配置只是为了查询数据而带来了很多复杂性。有了 Infino，开发者可以指向 Parquet 或 JSON，摄取数据，然后将他们的智能体指向 Infino 并开始查询。

## 谁受益于这项技术？Nwokah 列出了四个主要的软件工程从业者群体，他承诺他们可以从这里概述的方法中受益：

* 平台或数据 engineers 寻求掌控智能体的激增，拥有一个管理起来更加简单且成本低得多的技术栈。没有数据锁定（Nwokah 声称），因为他们的数据保留在他们的存储桶中，并且可由任何 Parquet 读取器读取。智能体可以通过一个接口结合结构化和非结构化数据。
* 安全 engineers 寻求围绕他们的智能体放置适当的治理层。通过数据的单一副本，智能体在其下运行的身份验证策略是集中且确定性地执行的，而不是跨一组 MCP 网关和 SaaS 连接器执行。
* ML 和数据科学团队进行特征探索。Infino 对结构化和非结构化数据进行搜索、过滤、连接和聚合，缩短了从凌乱数据到干净特征之间的时间。
* 软件 developers 构建跨代码、日志、CI 输出、问题和其他工程数据的智能体工作流。他们可以为所有这些提供一个查询接口，而不是为每个语料库给智能体一个不同的检索系统。

凭借其当前的架构，Nwokah 声称 Infino 的设计成本比传统搜索或分析基础设施便宜大约 10 倍。在其测试的工作负载中，Infino 自己发布的比较表明，它的成本比 Elasticsearch 便宜约 10.5 倍，比 OpenSearch 便宜 23 倍。

## 数十亿文档用例

Nwokah 确认，该公司已经在人物搜索、文档处理、产品分析和安全领域支持数十亿文档的用例。

他总结道：“我们特别针对已经在使用 Parquet 或考虑迁移到 Parquet，或者希望用更易于管理和更具可扩展性的东西替换其搜索工具的智能体用例团队进行了优化。”

该公司表示，其客户之一（Infino 未具名）正在将全公司范围内数 PB 的数据放在 Infino 上。Parquet 位于他们的存储桶中，并且仍可被不同团队的现有工具读取。同时，产品和工程团队获得了他们启动面向客户的 AI 原生解决方案所需的可扩展智能体基础设施。然后，开发者可以从单个接口控制他们的智能体。

Infino 首席执行官 [Nwokah](https://www.linkedin.com/in/ekechi/) 与联合创始人兼工程主管 [Vinay Kakade](https://www.linkedin.com/in/vinaykakade/)、联合创始人 [Asif Makhani](https://www.linkedin.com/in/asifmakhani/) 和首席架构师 [Murali Krishna](https://www.linkedin.com/in/muralikpbhat/) 共同创立了该公司。

该团队花了多年时间在亚马逊、谷歌和 LinkedIn（包括 AWS OpenSearch）构建和运营机器学习和搜索系统。智能体数据查询不断变化的性质是他们构建 Infino 的基本原理：使任何智能体都能够在单个查询中、在数据的一个副本上大规模查询数据。
