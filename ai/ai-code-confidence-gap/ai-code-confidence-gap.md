本文探讨了AI智能体加速代码生成带来的‘代码信心鸿沟’问题，提出通过意图、护栏、验证和证据四大支柱构建可信赖的软件交付体系。

> 译自：[The code confidence gap nobody’s talking about](https://thenewstack.io/ai-code-confidence-gap/)
> 
> 作者：Manish Kapur

**AI 改变了软件开发的经济学：** 过去需要数小时才能实现的任务，现在可以让智能体在几分钟内产出初始解决方案。随着智能体承担更广泛的任务，例如修改整个代码库中的代码、重构服务、编写测试以及准备合并请求，输出量将持续增长。

这是一个非同寻常的机遇，这也是为什么工程组织的下一个挑战不是生成更多的代码，而是建立对进入生产环境的[代码的信心](https://thenewstack.io/agentic-ai-verification-impact/)。在智能体软件工厂中，智能体编写、测试和提出更改的速度比人类逐行审查的速度还要快。

代码创作正在变得丰富；而代码信心则不然。

这种区别很重要，因为完成的合并请求并不等于可靠的结果。代码可能会编译并通过狭窄的测试套件，但仍然违反架构规范、引入安全漏洞、复制现有功能或产生稍后才会显现的维护成本。组织生成更改的速度越快，单纯依靠[英雄主义和人工审查](https://thenewstack.io/ai-code-review-burnout/)来捕获每个问题就越不可行。

> “代码创作正在变得丰富；而代码信心则不然。”

前进的道路是将代码信心视为可以设计到软件交付系统中的东西。一个有用的公式是：意图 × 护栏 × 验证 × Evidence（证据）。（是的，这里的乘法符号是刻意为之的。）这四个部分中的每一个都至关重要。其中三个部分的优势无法弥补第四部分的劣势。

没有验证的清晰意图无法防止错误。没有证据的强有力验证无法产生问责制。没有明确意图的护栏只会使模糊性自动化。没有独立验证的证据只是智能体所声称内容的记录。

以下是该公式每个部分在实践中的含义。

## 意图：使标准明确

智能体在追求既定目标方面非常强大。但是“构建支付功能”或“现代化此服务”对于生产代码库来说并不是一个充分的目标。组织对优质软件的定义包含更多内容，例如业务逻辑、安全期望、设计模式、性能需求、依赖项以及多年工程积累的规范。

意图是使这些期望明确的纪律。这意味着在智能体开始工作之前，定义更改的目标及其必须满足的标准。上下文越好，智能体花费在产出看似合理但不合适答案的循环就越少，开发人员以后需要进行的返工也就越少。

## 护栏：在产生风险之前塑造工作

护栏将意图转化为指导智能体操作方式的边界。它们可以定义允许哪些代码库、依赖项、数据或操作；哪些地方需要人类批准；以及哪些策略适用于给定类别的代码。

其目的不是限制每个有用的操作。而是为智能体提供足够的结构，使其能够高效且可预测地运行。精心设计的护栏使团队能够安全地授予更多自主权，因为每个人都了解该自主权适用的条件。

结果是可重复的自主权。团队无需将每次智能体驱动的更改都视为一次性实验，而是可以应用一致的边界，满怀信心地扩展智能体开发。

## 验证：独立检查每次更改

验证是测试信心的环节。随着智能体以不断扩大的规模生成代码，每次更改都需要针对重要的品质进行一致的评估：正确性、可靠性、安全性、可维护性以及是否符合组织自身的标准。

> “模型可以协助审查其自身的工作，但组织不应仅仅依靠产生更改的概率系统来确定该更改是否可以安全发布。”

独立性至关重要。模型可以协助审查其自身的工作，但组织不应仅仅依靠产生更改的概率系统来确定该更改是否可以安全发布。可重复的独立检查在各个模型、智能体和工具链之间提供了一个通用标准。当 AI 工具本身快速发展时，这一点尤其重要。

验证也需要在工作流程中进行，而不是作为一个缓慢的最终检查点。目标是在源头识别和修复问题，此时智能体或开发人员仍具备解决问题所需的上下文。

## Evidence（证据）：使信心可见且可审计

更改可能意图良好、管理严密且经过彻底检查。但工程领导者、审计人员以及负责生产的团队仍然需要知道发生了什么以及原因何在。Evidence（证据）是持久的记录：应用了哪些标准、检查了什么、发现了什么以及问题是如何解决的。

这在复杂和受监管的环境中最重要，但在任何地方它都很有价值。Evidence（证据）使质量可衡量，允许团队随着时间的推移改进他们的实践，并为组织快速行动提供可辩护的基础。

## 围绕信心构建工厂

智能体软件发展最具前景的愿景不是人类从过程中消失的愿景。而是人类、智能体和验证系统各自贡献其优势的愿景。智能体加速执行，工程师提供判断力和方向。交付系统提供使自主权得以扩展的标准、控制和Evidence（证据）。

> “智能体软件发展最具前景的愿景不是人类从过程中消失的愿景。而是人类、智能体和验证系统各自贡献其优势的愿景。”

成功的组织将是那些在任何规模、以智能体速度将代码信心融入每一次更改的组织。

这才是[智能体软件工厂](https://thenewstack.io/warp-software-factory-infrastructure/)的真正工作，生产出组织有信心为其背书的软件。

下次当智能体打开合并请求时，从四个问题开始：

* 智能体在开始之前知道您的标准吗？
* 允许它触碰什么，什么需要人类决策？
* 除了编写更改的模型之外，还有其他东西检查过它吗？
* 您能展示发现了什么以及它是如何解决的吗？

无论哪个答案是“否”，这就是您的信心鸿沟所在。首先在那里弥合它。
