JetBrains 正在敦促其 Cadence 云开发服务的用户轮换凭据，并对之前的执行任务及其输出结果保持不信任态度，此前攻击者利用了 JetBrains 未能修补的服务器上的一个关键 TeamCity 漏洞。

这一幕极具讽刺意味。JetBrains 于 7 月 27 日披露了 [CVE-2026-63077](https://blog.jetbrains.com/teamcity/2026/07/cve-2026-63077/)，这是一个存在于 TeamCity On-Premises 中的关键漏洞。该缺陷允许未经身份验证且拥有 HTTP 或 HTTPS 访问权限的攻击者，在存在漏洞的 TeamCity 服务器上以 TeamCity 服务器进程的权限执行任意操作系统命令。

到 8 月 7 日，该公司宣布攻击者已经开始利用未修补的 TeamCity 服务器。

但仍有一个受影响的服务器暴露在外：JetBrains 自己的服务器。

“该服务器本应作为我们响应漏洞补丁计划的一部分进行修补，但事实并非如此，”JetBrains 在披露 Cadence 事件时承认道。

> “该服务器本应作为我们响应漏洞补丁计划的一部分进行修补，但事实并非如此，”

## Cadence 未修补的 TeamCity 服务器

攻击者瞄准了 `api.cadence.jetbrains.com`，这是 JetBrains 旗下 PyCharm 云计算服务 Cadence 后端的服务器。JetBrains 于 8 月 23 日发现了此次攻击，并于次日将服务器下线。他们的调查显示，恶意活动始于 8 月 8 日，因此受影响的周期为 8 月 8 日至 8 月 24 日。

Cadence 通过一个可选插件与 PyCharm 集成，使开发人员能够在云端计算资源上运行项目。TeamCity 位于该服务后端，负责编排这些工作负载。

这使得受攻击的服务器处于开发环境中一个特别敏感的位置。

## 泄露的凭据与源代码

JetBrains 表示，攻击者获取了一份 2024 年完整的 Cadence 服务器备份，这可能导致其中存储的所有内容被曝光，包括凭据、配置文件、工件和日志。

该公司还证实，多个 AWS IAM 用户及其关联凭据遭到破坏，其中包括使用过 Cadence 的 JetBrains 员工所属的 IAM 用户。

攻击者访问了该服务所使用的 JetBrains AWS 账户内的 S3 存储桶中的文件。JetBrains 目前仍在确定影响的全部范围，并表示尚不清楚客户的存储桶是否遭到访问。

使用 PyCharm 插件的开发人员在运行项目前可以将项目文件同步到 Cadence，因此源代码以及这些项目中包含的任何凭据或配置文件也可能已泄露。

此次入侵还泄露了用户名、真实姓名、电子邮件地址、最后登录时间戳和最后访问 IP 地址。在 Cadence 执行期间使用的凭据可能也提供了对其他已连接服务的访问权限。

## 供应链风险迅速复合

JetBrains 表示，用户应将存储在 Cadence 中、包含在被盗备份中或在执行期间使用的任何凭据或机密视为已泄露。

这意味着可能需要轮换 AWS、Azure 和 Google Cloud 凭据，以及 GitHub、GitLab 和 Bitbucket 的令牌。JetBrains 还警告了 npm、Maven、NuGet、PyPI 以及 Docker Hub、ECR、GCR 和 ACR 等容器注册表的凭据风险。

对这些注册表的访问又引发了另一个问题。拥有发布凭据的攻击者可以推送恶意包，并被拉取到其他项目中，类似于[最近一次利用来源证明在软件供应链中传播的 npm 攻击](https://thenewstack.io/npm-supply-chain-worm-attack/)。

该警告还涵盖了 Slack 令牌、Webhooks、API 令牌、SSH 和部署密钥、服务账户凭据以及签名密钥或证书。

据 JetBrains 称，在受影响期间通过 Cadence 运行的任何内容，包括产生的输出，都应被视为不可信。这种担忧不仅限于暴露的数据和凭据；Cadence 在此期间运行的任何内容都有可能已被篡改。

CI/CD 和远程执行系统通常有权访问私有存储库、依赖项、云存储、包注册表和部署系统。它们在软件交付中的核心作用是[导致 CI/CD 基础设施成为收购目标的原因之一](https://thenewstack.io/anthropic-mendral-cicd-acquihire/)，这也为攻击者在获得访问权限后提供了更多的攻击路径。一旦环境本身受到破坏，开发人员就不能假设流经其中的凭据或它生成的工件是安全的。

> 一旦环境本身受到破坏，开发人员就不能假设流经其中的凭据或它生成的工件是安全的。

## 审计日志揭示横向移动

更改可能已泄露的凭据只是 JetBrains 建议的一部分。用户还需要检查这些凭据是否在其他地方被使用过，以及与 Cadence 连接的系统中是否有任何变动。

JetBrains 建议检查源代码控制审计日志，查看是否存在异常的存储库克隆或下载、未经授权的提交，以及对存储库机密或 Webhooks 的更改。用户还应留意新增或更改的个人访问令牌、API 令牌和 SSH 密钥。

> JetBrains 建议检查源代码控制审计日志，查看是否存在异常的存储库克隆或下载、未经授权的提交，以及对存储库机密或 Webhooks 的更改。

云环境也需要同样仔细的审查。JetBrains 表示，用户应查找异常的 IAM 更改、新用户或服务账户，以及对 S3 存储桶等存储空间的异常访问。身份验证日志还可以显示 Cadence 中使用的凭据是否随后在未知地点被使用。

应检查包存储库和发布历史记录，查看是否有异常的发布或更改，特别是当 Cadence 拥有可以发布包或工件的凭据时。

由于 JetBrains 将之前的 Cadence 执行及其输出视为不可信，调查范围已不仅限于检查账户日志。开发人员可能还需要审查受影响期间通过该服务制作的工件，并确保它们与可信的源代码和预期的构建结果相符。

该公司公布了 6 个与检测到的攻击行为相关的 IP 地址：150.109.230.104、43.153.227.206、62.210.127.48、210.247.242.190、15.235.225.205 和 152.233.30.18，并警告称这些指标并不全面，因此未发现这些 IP 并不意味着账户或系统没有受到破坏。
