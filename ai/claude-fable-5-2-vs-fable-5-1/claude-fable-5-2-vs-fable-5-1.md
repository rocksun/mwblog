本文对比测试了Anthropic的Claude Fable 5.2与5.1版本。实测表明，新版本Fable 5.2显著减少了误报拒绝（refusals），在Webhook聊天、签名检查器和登录仓库修复等任务中表现更稳定，生成速度更快，推理能力更强。

> 译自：[The tests](https://thenewstack.io/claude-fable-5-2-vs-fable-5-1/)
> 
> 作者：Jessica Wachtel

**Anthropic 的 Claude Fable 5.2 承诺减少拒绝次数**并降低 Token 价格，但在我们的直接编码对比测试中，这些变化的效果大不相同。

Anthropic 在安全防护拦截、输出速度和 API 定价方面，将 [Fable 5.2](https://thenewstack.io/anthropic-fable-coding-upgrade/) 与其前身 [Fable 5.1](https://thenewstack.io/anthropic-fable-5-1-launch/) 进行了对比。[该公司表示](https://www.anthropic.com/claude-fable-and-mythos-5-2)，在 claude.ai、Claude Code 和 Cowork 的早期测试中，Fable 5.2 的总体安全防护拦截触发率比 Fable 5.1 低约 55%，在网络安全领域更是降低了约 60%。该公司还表示，Fable 5.2 的输出生成速度提升高达 30%，并列出了[标准 API 费率](https://platform.claude.com/docs/en/release-notes/overview)：每百万未缓存输入 Token 8 美元，每百万输出 Token 40 美元。这两个费率都比 Fable 5.1 的 10 美元和 50 美元低 20%。

我在三个开发者任务上对比了 Fable 5.2 和 Fable 5.1，并追踪了拒绝次数、准确率、Token 消耗、预估成本以及耗时。每个模型对每个任务或版本只运行一次（包括 10 月份的 Fable 5.1 webhook 测试结果）。这是一个小型样本，且 API 运行的设置与 Anthropic 的安全防护测试不同。

## 测试

对于新的运行测试，我使用了 Anthropic 的 API，两个模型均采用[默认的高努力设置（High effort setting）](https://platform.claude.com/docs/en/models/fable-5-1/overview)，没有设置轮次上限或回退模型。脚本根据我为测试创建的标准答案对每次运行进行评分。美元数字是预估的 API 成本。Anthropic [对未缓存输入、缓存读取、缓存写入和输出分别定价](https://platform.claude.com/docs/en/models/fable-5-2/whats-new-fable-5-2#pricing)。

* **Webhook 聊天**：我重用了 10 月份首次在 Fable 5.1 上运行的包含 50 个轮次的脚本化聊天。它模拟了一位开发主管构建小型 webhook 中继的过程。聊天包含 25 条项目规则，其中 8 条在后期发生变化，3 条仅为隐含规则。最后，模型编写配置和代码，然后参加一个包含 8 个问题的回忆测验。
* **签名检查器**：我为每个模型提供了一份编写好的代码规范，用于验证已签名的 webhook、拒绝重放攻击并限制发送者的速率，随后发送了一项变更请求。一套隐藏的 50 项测试用例对最终的代码输出进行了评分。
* **登录仓库修复**：每个模型都在一个小型登录库中作为智能体工作，该库在密码、锁定、重置 Token 和会话方面存在相互关联的 Bug。该库还有一个错误的测试，模型应当报告它但不应进行修改。

### Webhook 聊天

在我用于对比的 10 月份 [Fable 5.1 运行](https://thenewstack.io/muse-wonder-claude-fable/)中，API 在 50 个轮次中拒绝了 34 次。第一次拒绝发生在第 5 轮，当时我要求模型从环境变量中读取中继的目标 URL。在那次 10 月份的运行中，我将提示词保留在聊天历史中，并丢弃了被拒绝的模型响应。Fable 5.1 还拒绝了最后的代码和测验，因此两项得分均为零。该任务是构建一个普通的后端中继。

> 第一次拒绝发生在第 5 轮，当时我要求模型从环境变量中读取中继的目标 URL。

Fable 5.2 在没有遭到任何拒绝的情况下完成了相同的脚本。这为我提供了一次完整的运行结果，以便评估长对话的记忆能力。其代码使用了所有 8 条规则的最新版本（这些规则在中途发生了变化），在测验中，对于没有答案的 3 个问题，它回答了“未知”。Fable 5.2 没有凭猜测填补空白。

具体数据：

• **Fable 5.2**：50 轮，输入 298,709 Token，输出 41,828 Token（包含 28,550 推理 Token），花费 4.06 美元，耗时 427 秒。

• **Fable 5.1（10 月）**：50 轮中有 34 轮被拒绝，没有代码或测验答案。

### 签名检查器

Fable 5.1 在不到一秒钟内就拒绝了该测试的两个轮次，API 将这两次拒绝都标记为“网络安全（cyber）”。该规范要求编写能够验证已签名 webhook、拒绝重放并限制发送者速率的代码。API 在这两轮中均未返回任何输出。Anthropic 表示，[良性的安全工作可能会触发其网络安全分类器](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback)。

Fable 5.2 接收了相同的规范，处理了变更请求，并通过了所有 50 个隐藏测试，包括时间戳、轮换密钥和重放攻击的边缘情况。

具体数据：

* **Fable 5.2**：2 轮，输入 21,299 Token，输出 26,167 Token（包含 18,407 推理 Token），花费 1.22 美元，耗时 253 秒。
* **Fable 5.1**：2 轮，均被拒绝，报告输入 Token 3,206，输出 Token 0，根据 Anthropic 关于[输出前网络安全拒绝的计费规则](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback#how-refusals-are-billed)花费 0.00 美元，耗时 2 秒。

### 登录仓库修复

这是唯一一个两个模型都完成了工作的测试，展示了在排除拒绝情况后它们的对比结果。由于模型不断获得满分，我增加了测试难度并重新运行了两次。测试之间的区别如下：

* **版本 1**：该库在处理密码哈希、锁定、重置 Token 和会话的四个模块中存在 Bug。它还有一个错误的测试。
* **版本 2**：我添加了一个带有自身 Bug 的一次性代码模块，并收紧了现有模块中的规则。用户名必须在各种 Unicode 形式下一一匹配，会话必须能够处理倒退的时钟。
* **版本 3**：我添加了一个必须对机密进行脱敏的审计日志和一个速率限制器。这两个模块都没有自带任何测试。

两个模型在登录仓库修复的所有三个版本中打成平手。每个版本均获得 50/50 的满分，修复了评分器涵盖的 Bug 并报告了错误的测试而未对其进行修改。

Fable 5.1 在登录仓库修复中从未拒绝过，尽管该任务涉及密码、锁定和重置 Token。

在三个版本中，将总输出 Token（包含推理）除以总耗时，Fable 5.2 约为每秒 107 个 Token，Fable 5.1 为 82 个。耗时包含了整个任务的运行时间。Fable 5.2 在每个版本中花费了 4 个轮次，而 Fable 5.1 分别花费了 7、21 和 25 个轮次。Fable 5.2 在每个版本中也产生了更多的推理 Token。

Fable 5.2 以更快的速度和更低的预估成本完成了前两个版本。但在第三个版本中，它花费的时间更长，成本更高。

具体数据：

* 版本 1
  + **Fable 5.2**：4 轮，输入 16,149，输出 4,502（1,178 推理），0.27 美元，43 秒。
  + **Fable 5.1**：7 轮，输入 33,935，输出 4,761（1,149 推理），0.36 美元，52 秒。
* 版本 2
  + **Fable 5.2**：4 轮，输入 24,081，输出 10,024（4,887 推理），0.56 美元，95 秒。
  + **Fable 5.1**：21 轮，输入 139,189，输出 9,475（4,018 推理），0.68 美元，118 秒。
* 版本 3
  + **Fable 5.2**：4 轮，输入 34,269，输出 17,964（10,578 推理），0.96 美元，166 秒。
  + **Fable 5.1**：25 轮，输入 208,826，输出 10,638（4,342 推理），0.79 美元，132 秒。

## 结果

下面的 Token、成本和时间总计涵盖了签名检查器以及所有三个登录仓库版本。Fable 5.1 在签名检查器上没有产生输出，而 Fable 5.2 花费了 253 秒和约 1.22 美元完成了该任务。在两个模型都完成了的三个登录版本中，耗时和预估成本非常接近。合并总计包含了仅由 Fable 5.2 在签名检查器上完成的工作。

|  |  |  |
| --- | --- | --- |
| **测试** | **Claude Fable 5.2** | **Claude Fable 5.1** |
| Webhook 聊天拒绝次数（共 50 次） | 0 | 34（10 月） |
| Webhook 聊天代码与测验 | 25/25，8/8 | 0/25，0/8（10 月） |
| 签名检查器（共 50 次） | 50 | 0，两轮均被拒绝 |
| 登录仓库修复，3 个版本（共 150 次） | 150 | 150 |
| 输入/输出 Token（签名检查器与登录修复） | 95,798 / 58,657 | 385,156 / 24,874 |
| 预估成本（签名检查器与登录修复，显示估计值的总和） | $3.01 | $1.83 |
| 总时间（签名检查器与登录修复，显示时间的总和） | 557 秒 | 304 秒 |

### 我的看法如何？

在我的测试中，Fable 5.2 带来的最大改进是减少了拒绝次数。Fable 5.1 阻止了普通的 webhook 和签名检查工作，而 Fable 5.2 在没有一次拒绝的情况下完成了这两项工作。Anthropic 表示，较新的模型[仍然在使用网络安全防护机制](https://www.anthropic.com/claude-fable-and-mythos-5-2#safeguards)。

> 在我的测试中，Fable 5.2 带来的最大改进是减少了拒绝次数。

在三个登录仓库版本中，Fable 5.2 在每秒耗时内产生的输出 Token（包含推理）多出约 30%，同时总耗时大致相当。Fable 5.2 的总运行时间为 304 秒，Fable 5.1 为 302 秒。

显示的成本估计值分别加起来为 1.79 美元和 1.83 美元，这些运行节省了约 2% 的费用。Anthropic 20% 的降价适用于其标准的每 Token 费率。我为每个模型各运行了每个版本一次，因此建议你在自己的工作负载上亲自尝试这两个模型，看看你的实际数据如何。
