**更早期的数据库协议诞生于大数据时代之前。**有些协议至今仍在逐行发送结果，并且在每一行中重复列名和数据类型等详细信息。[DuckLabs](https://ducklabs.com/) 产品团队负责人 [Guillermo Sánchez Dionis](https://www.linkedin.com/in/guillermo-s%C3%A1nchez-dionis/) 表示，这就导致了“相当臃肿的消息”。当你需要传输大型查询结果时，这些开销会不断累积。

DuckDB 给出的答案是 [Quack](https://duckdb.org/quack/)，这是一个基于 HTTP 的协议，能够在 DuckDB 生成结果的同时，以列式数据块批次流式传输查询结果。该协议于 5 月发布预览版，并于 10 月作为 DuckDB 2.0.0 LTS 的一部分正式发布。

在阿姆斯特丹 DuckLabs 总部录制的最新一期 *The New Stack* 播客中，Sánchez Dionis 解释了这种设计如何让开发者在查询仍在运行时就开始处理结果。

数据库协议是一套正式的规则和消息格式，规定了客户端应用程序如何与数据库服务器通信。它充当一种专用语言，使软件应用程序能够通过网络以安全的方式发送 SQL 查询、接收结构化数据表并管理事务。它负责处理连接与身份验证、查询打包、数据序列化以及错误管理。

但据 Sánchez Dionis 介绍，大多数协议是在大数据时代之前为其他类型的系统设计的，序列化的是行而不是列。他还指出，它们添加了许多不必要的数据，例如每行都附带列类型和列名。

“它变成了一个相当臃肿的消息。这不仅让该协议不适合分析型系统，而且本身也非常笨重。”他认为。随着协议向分析型系统演进，它们确实开始采用列式存储，但“它们仍然在做每次只序列化一个值之类的低效操作。现代系统正试图趋同于使用向量化执行，以便一次序列化更多值，并尝试使用更高效的列式数据格式表示来进行网络传输。”

而他强调，Quack 协议旨在采用一种截然不同且高度高效的方法。

Quack 是 DuckDB 基于 HTTP 的客户端/服务器协议，其首个生产版本已于 10 月 21 日随 DuckDB 2.0.0 一同发布。这不仅标志着 Quack 走出了预览阶段，该协议现在还提供了一系列对开发者友好的功能：

* CONNECT 语句允许开发者通过标准 SQL 命令附加并查询远程 Quack 服务器。
* 新增的 -serve 命令行参数可从命令行即时启动 Quack 服务器实例，-connect 则用于连接到实例。
* 多个客户端可以并发写入同一个数据库，事务在 DuckDB 的多版本并发控制（MVCC）隔离机制下进行处理。

“Quack 使用 DuckDB 的数据块——也就是我们的列式数据表示。由于我们是向量化引擎，因此序列化的方式也非常高效。同时，我们还确保以流式方式发送结果。”Sánchez Dionis 解释道。

“最重要的一点是与引擎的紧耦合。一旦开始产生结果，你无需等待查询执行完毕再一次性序列化所有结果，而是在引擎输出结果的瞬间就进行序列化并发送。因此，客户端可以持续消费结果，而无需让引擎停下来。”

他表示，对开发者而言，这意味着他们无需做任何额外操作。

> “我认为你能看到的最大优势，就是内存占用会非常小”

“你在自己的笔记本电脑上舒适地运行查询，就能直接获得流式返回的结果。我认为你能看到的最大优势，就是内存占用会非常小，”他说，“Quack 的酷之处在于，无论你身在何处，都可以安装并加载它。你还可以在同一台笔记本电脑上使用 Quack 扩展创建另一个客户端，它们彼此之间就能直接通信。”

Sánchez Dionis 继续说道，至于部署多少台 DuckDB 服务器的规模，完全由你和你的团队决定，而在服务器上运行它的开销几乎为零——这也是 Quack 迄今为止最大的效率提升。

随着 DuckLabs 团队致力于提升服务器端的稳定性，预计在即将推出的 DuckDB 2.0 补丁版本中，Quack 还将迎来更多改进。
