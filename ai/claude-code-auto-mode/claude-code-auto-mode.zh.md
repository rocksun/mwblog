**在 Claude Code 的早期阶段**，你似乎只有两个选择：要么批准编程代理所做的每一件事——这非常令人烦恼——要么完全放权，但这又极其危险。

今年早些时候，Anthropic 推出了[自动模式](https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode)，它使用一个独立的分类器模型，允许 Claude 自行决定何时某项操作过于危险而需要人类介入。

从 8 月 14 日起，这将[成为 Pro、Max 和 Team 用户的新默认设置](https://claude.com/blog/auto-mode-default-in-claude-code)（目前企业用户、Claude API 和云平台用户仍需手动开启，计划在下个月内推广为默认设置），因为事实证明，人类在不断被要求授予权限时，表现并不理想。

## 97% 的问题

确实，正如 Anthropic 自己的研究显示，用户目前会批准 97% 的权限提示。

“虽然大多数提示可能都是安全、常规的命令，但如此高的批准率表明，许多用户是在反射性地点击，而不是在审查每一条命令，” Anthropic 指出。

![](https://cdn.thenewstack.io/media/2026/08/54ffa374-hpi2quja8aaun3e-1024x631.jpeg)

*图片来源：Anthropic*

通过与 1,000 多名测试人员合作，团队还发现，人类仅能捕捉到 13.6% 的危险命令，而处于自动模式下的 Claude Code 能捕捉到 89%。

会话持续的时间越长，人类测试人员的表现就越差。在 50 次提示后，测试人员仅发现了 5% 的危险命令（不过尚不清楚 Anthropic 在这些漫长的会话中是否为他们提供了咖啡）。

> 事实证明，人类在不断被要求授予权限时表现并不理想：在 50 次提示后，测试人员仅发现了 5% 的危险命令。

Anthropic 认为，减少权限提示意味着用户将有更多时间去真正阅读和评估那些确实弹出的提示。

在实践中，当分类器标记某个命令时，自动模式会直接阻止它，而不是请求权限。Claude 通常会寻找更安全的方法来完成同样的任务，或者返回给用户进行明确的批准。

此外还有一个后备机制：在连续拦截三次，或在单次会话中拦截二十次后，自动模式会将控制权交还给用户，并恢复为手动批准。

正如 Anthropic 也[提到](https://x.com/ClaudeDevs/status/2085794863786958988)的那样，随着代理现在往往需要运行更长时间，自动模式使得在进行这些长达数小时的任务时更加轻松，无需花费数小时仅仅去做[机器人看护（botsitting）](https://www.businessinsider.com/botsitting-ai-hidden-human-labor-at-work-2026-6)。

## 强化自动模式

在发布之前，Anthropic 也花时间加强了自动模式。

其中最重大的变化是“强制拒绝”。Anthropic 表示，分类器的设计目标是永远不允许批准数据外泄，例如将代码或机密发送到外部目的地。要执行这样的操作，开发者必须切换出自动模式，或亲自运行该命令。

组织还可以添加自己的“强制拒绝”规则，针对那些即使在用户请求时也绝对不允许的操作。

> 分类器现在还针对如何访问和共享机密及机密数据制定了明确的规则。

分类器现在针对如何访问和共享机密及机密数据制定了明确的规则，并在执行操作前检查 git push 或 pull request 的目标是公开的、私有的还是受信任的。毕竟，同样的推送操作，取决于落点在哪里，可能是常规操作，也可能是数据外泄。

此外，在执行 git reset --hard 等破坏性命令之前，分类器现在会查看存储库的 git 状态，因此自动模式知道哪些未提交的工作即将被丢弃。API 端的探针还会筛选 Claude 从网页、文件和工具输出中拉取的内容，以防范提示注入攻击，并在发现异常时向 Claude 的上下文添加警告。

为了对这项工作进行压力测试，Anthropic 与 Apollo Research 进行了为期两周的红队测试试点，将合成攻击注入到真实的工作流中。在加强之前，分类器漏掉了 12% 的这些攻击；之后，这一数字在保留的测试集上降至了 7%。

## 自动模式对比提示注入

Anthropic 也趁此机会将其与最大的竞争对手 OpenAI 进行了比较。当然，如果结果不理想，公司是不会这么做的，但 Anthropic 确实委托了第三方来测试自动模式在预防提示注入攻击方面的表现。

Trajectory Labs 发现，在使用 Anthropic 模型处于自动模式时，其尝试的 720 次攻击中没有一次成功（即使在权限完全被绕过的情况下，Claude Sonnet、Fable 和 Opus 5 也仅放行了 0.09% 的攻击）。

而 OpenAI 的 GPT-5.6 Sol in Codex 在全访问模式下放行了 19% 的攻击，在其自动审查模式下放行了略低于 6% 的攻击。

![](https://cdn.thenewstack.io/media/2026/08/4674a74b-6a75fafde538ce42b19d5742_image3-2-1024x666.png)

图片来源：Anthropic。

不过，Anthropic 自己也指出，自动模式是一个分类器，而不是一种担保——它降低了风险，但并没有消除风险。对于高风险的生产基础设施变更，该公司仍然建议保持人工参与。

## 附赠：Claude Code 会话现在可以互相私信了

除了权限更新外，Anthropic 周五还宣布，如果你运行并行的 Claude Code 会话，它们现在可以进行交流。如果你有多个会话正在处理相关问题，并且它们需要相互通知正在处理的代码变更，这一点尤其有用。

“与其在另一个会话中重复解释自己，你现在可以直接告诉 Claude 去做。它会发送一个摘要（而不是你的历史记录或文件），然后另一个会话会在任务进行到一半时接手，” Anthropic 在 X 上[解释道](https://x.com/ClaudeDevs/status/2085817074816070014)。
