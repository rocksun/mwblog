本文通过修复Bug、代码审查和编写代码三个真实开发任务，对比了Claude Fable 5.2与GPT-6 Astra的性能。测试表明Fable 5.2代码审查更仔细但成本更高，而Astra性价比更高且速度更快。

> 译自：[The tests](https://thenewstack.io/claude-fable-5-2-vs-gpt-6-astra/)
> 
> 作者：Jessica Wachtel

**Anthropic 正在将其新模型** [Claude Fable 5.2](https://thenewstack.io/anthropic-fable-coding-upgrade/) 定位用于高要求的编码和技术工作。Anthropic 于 11 月 9 日推出了 Fable 5.2，并报道其在两个编码基准测试中的得分高于 OpenAI 的 GPT-6 Astra。Fable 5.2 还具有更低的标准 API 费率。

[Anthropic 的发布基准测试](https://www.anthropic.com/claude-fable-and-mythos-5-2)显示，在 FrontierCode 2.0 上，Fable 5.2 以 49.1% 对 42.8% 领先 Astra；在 FrontierSWE v2 上以 69.9% 对 65.5% 领先。Fable 的 49.1% 是在高投入（high effort）下取得的。在 High 级别（[Claude API 上的默认设置](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2)），它的得分为 45.3%。基准测试的领先并不总是能转化为实际工作。

成本方面并不像价目表那样简单。Token 是模型读取和编写的一块块文本，AI 公司按此计费。按照标准的 API 费率，Fable 5.2 的未缓存输入 Token 价格为每百万 8 美元，输出 Token 价格为每百万 40 美元。[OpenAI 在 9 月推出了 GPT-6 Astra](https://thenewstack.io/openai-gpt6-astra-benchmarks/)，其标准 API 费率为每百万未缓存输入 Token 10 美元，输出 Token 每百万 50 美元。“每个任务的价格才是最重要的，”OpenAI 总裁 Greg Brockman 在 Astra 的发布会上说。两个 API 都对[作为输出的推理 Token](https://developers.openai.com/api/docs/guides/reasoning) 收费，并且对[缓存的输入有单独的费率](https://developers.openai.com/api/docs/guides/prompt-caching)。

根据我的经验，Anthropic 的模型比 OpenAI 的模型消耗了更多的 Token。我将这一定位付诸测试，在模拟真实开发者工作的任务中让 Fable 5.2 与 Astra 进行了较量。

## 测试

我在每个供应商的 API 上使用默认设置，让两个模型对相同的三个任务各运行了一次。每个测试值 50 分，我使用了一个脚本来给所有答案评分。以下是测试内容：

* **Bug 修复**：我在一个 2,600 行的计费代码库中植入了 10 个 Bug，并写了一张描述 10 个客户投诉的支持工单。工单对原因的猜测是错误的，代码库本身的两个测试是错误的，并且其中一个 Bug 只有在另一个 Bug 被修复后才会显现。
* **代码审查**：我在一个欧盟发票包中，针对 27 个国家的 VAT ID 检查、IBAN 规则、欧洲中央银行支付日历以及 50 个区域设置的日期格式，植入了 45 个缺陷。模型必须用代码出错的输入来证明每个缺陷并识别出正确答案。标记误报会扣除模型的分数。
* **代码编写**：模型从头编写相同的辅助工具，包括 27 个国家的 VAT ID 验证、34 个国家的 IBAN 检查、支付日历和长日期。

### Bug 修复

Fable 5.2 和 Astra 修复了所有的 10 个 Bug 并通过了所有 50 个隐藏检查，双方都在 12 轮内完成（相同的轮数让我感到惊讶）。

区别在于每个模型为达到这一目标花费了多少代价。Fable 5.2 使用了超过 17,000 个推理 Token，而 Astra 使用了 819 个（令人惊叹）。Astra 在大约两分钟内通过了检查，估计成本为 98 美分。Fable 5.2 花费了五分钟以上，估计成本为 2.51 美元。

数据：

* **Fable 5.2**：12 轮，输入 696,863，输出 36,135（17,387 个推理），2.51 美元，326 秒。
* **Astra**：12 轮，输入 231,854，输出 6,823（819 个推理），0.98 美元，122 秒。

### 代码审查

这是唯一一个得分不同的测试。Fable 5.2 得分 49，Astra 得分 45。Fable 5.2 证明了 45 个缺陷中的 44 个，在 71 个发现中没有产生误报。Astra 证明了 41 个，并错误地将一个西班牙 ID 分类为有效。Astra 遗漏了西班牙、爱尔兰和卢森堡校验位规则中的缺陷。两个模型都遗漏了同一个西班牙缺陷：一个 23 字母查找表中的两个字母颠倒。

Fable 5.2 的彻底性是有代价的。它的成本是 Astra 的六倍以上，时间是 Astra 的四倍以上。如果你的代码处理发票（或简单的审批），审查遗漏的一个验证规则可能会导致真实发票被拒绝，因此 Fable 5.2 多出的四分可能物有所值。对于常规审查，Astra 以 16% 的成本发现了 91% 的缺陷。每个模型只运行了一次，因此四分的差距在另一次运行中可能会发生变化。

数据：

* **Fable 5.2**：26 轮，输入 2,207,564，输出 103,240（77,641 个推理），6.05 美元，993 秒。
* **Astra**：12 轮，输入 192,018，输出 8,664（4,307 个推理），0.95 美元，227 秒。

### 代码编写

两个模型的得分都是 50 分（满分 50）。它们各自在没有外部库支持的情况下，为 27 个国家的 VAT ID 和 34 个国家的 IBAN 编写了可用的检查程序。两个模型在这里都没有遇到困难。两者都在一次运行中通过了所有检查。

Astra 花费了 23 轮，几乎和 Fable 5.2 的 24 轮一样多。为了获得相同的分数，Fable 5.2 的成本仍然是前者的 2.3 倍，时间是前者的 1.7 倍。在这次运行中，额外的 Token 并没有提高分数。

数据：

* Fable 5.2：24 轮，输入 1,495,712，输出 87,542（47,458 个推理），4.83 美元，838 秒。
* Astra：23 轮，输入 460,271，输出 24,007（9,328 个推理），2.06 美元，483 秒。

## 结果

|  |  |  |
| --- | --- | --- |
| **测试** | **Claude Fable 5.2** | **GPT-6 Astra** |
| Bug 修复（满分 50） | 50 | 50 |
| 代码审查（满分 50） | 49 | 45 |
| 代码编写（满分 50） | 50 | 50 |
| 总输入/输出 Token | 4,400,139 / 226,917 | 884,143 / 39,494 |
| 估计成本 | $13.39 | $3.99 |
| 总时间 | 2,157 秒 | 832 秒 |

Fable 5.2 在代码审查中领先，在其他两个任务上与 Astra 打平。在两个打平的任务中，其估计的 API 成本是 Astra 的 2.4 倍（7.34 美元对 3.04 美元），花费的时间是 Astra 的 1.9 倍（1,164 对 605 秒）。

### 我是怎么想的？

对于此类任务，我会从 Astra 开始。它在 Bug 修复和代码编写上与 Fable 5.2 的得分不相上下，但估计成本仅为后者的 41% 左右，并且更快地完成了所有三个任务。我会考虑将 Fable 5.2 用于仔细的代码审查，在这次测试中它多发现了三个缺陷。两个模型都遗漏了缺陷。

Fable 5.2 的标准 Token 费率较低，但在完成这三次运行中，它消耗的 Token 大约是 Astra 的五倍。Brockman 关于每个任务价格的观点在这里得到了印证。
