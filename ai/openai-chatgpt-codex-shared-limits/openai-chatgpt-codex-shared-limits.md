OpenAI计划自12月起将ChatGPT与Codex的Token使用额度合并为一个通用资源池。此举旨在整合对话与智能体能力，但引发了订阅用户的强烈担忧，他们担心高强度的编码任务会挤占日常对话额度，并呼吁保持独立配额或提供更多透明度。

> 译自：[OpenAI’s new shared usage limit pits ChatGPT against Codex](https://thenewstack.io/openai-chatgpt-codex-shared-limits/)
> 
> 作者：Paul Sawers

OpenAI 透露了将 ChatGPT 和 Codex 的使用配额进行合并的计划，作为其将对话式 AI 和智能体能力整合到单一体验中的更广泛努力的一部分。

在周末悄悄发布的一篇[帮助文章](https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits)中，该公司确认这些更改将于“12月开始”生效，影响 Plus、Pro 和 Business 订阅用户。在新系统中，ChatGPT 对话和 Codex 任务将从一个共同的 Token 池中扣除，要求更高的模型和更复杂的任务将消耗更大的份额——尽管 OpenAI 尚未透露合并后的配额究竟会有多丰厚。

即时聊天（ChatGPT 针对日常问题和任务的快速响应模式）将不受此限制。

## OpenAI 的产品走向融合

这些变化是 OpenAI 努力将其不断增长的 AI 产品系列归于统一旗下的最新一步。

7月份，该公司[推出了 ChatGPT Work](https://openai.com/index/chatgpt-for-your-most-ambitious-work/)，这是一个构建在其 Codex 编码技术之上的智能体工具，允许用户委派复杂任务，例如研究主题、分析数据以及制作文档、演示文稿和电子表格。其理念是将 Codex 的能力扩展到软件开发之外，允许知识工作者将 AI 智能体用于日常商业任务。

正如 *The New Stack* [当时报道的那样](https://thenewstack.io/openai-codex-work-atlas/)，这次发布还将 ChatGPT 和 Codex 合并到一个单一的桌面应用程序中，为对话、智能体任务和编码提供了专门的界面。

ChatGPT Work 加入了一个不断扩展的专业工具系列，其中包括[3月份首次亮相的](https://openai.com/index/chatgpt-for-excel/)用于 Excel 的 ChatGPT，后来又扩展到了 [Google Sheets](http://help.openai.com/en/articles/20001063-chatgpt-for-excel-and-google-sheets)。

值得注意的是，这些产品已经有了重叠的使用安排。目前，Codex、ChatGPT Work、Excel 版 ChatGPT 以及[工作区智能体](https://openai.com/index/introducing-workspace-agents-in-chatgpt/)都从[一个共享的智能体配额中扣除](https://help.openai.com/en/articles/20001516-managing-usage-with-gpt-6-astra-in-work-and-codex)，而常规的 ChatGPT 对话则有单独的使用限制。

正是这种分离状态将在 12 月发生改变，这将使开发者陷入这样一种境地：密集的 Codex 会话会侵蚀可用于 ChatGPT 对话的配额，反之亦然。

## “ChatGPT 和 Codex 服务于不同的目的”

在将对话产品和智能体产品拉近距离方面，OpenAI 并不孤单。9月，[Anthropic 将 Claude Chat 和 Cowork](https://thenewstack.io/anthropic-claude-unified-interface/) 合并到一个单一界面中，[允许用户](https://thenewstack.io/claude-cowork-vs-chatgpt-work-benchmark/)在同一个对话中从提问过渡到委派更复杂的任务。

这表明两家最大的前沿 AI 实验室正在追求一个相似的目标：让用户更容易在提问和执行更实质性的任务之间切换，而无需浏览不同的产品。然而，OpenAI 合并使用配额的决定遭到了订阅用户的反对，他们担心这一变化可能会减少他们对已经付费购买的工具的访问权限。

> “ChatGPT 和 Codex 服务于不同的目的，它们的使用限制应该保持独立。”

在周六于 OpenAI 开发者论坛上[发起的一场讨论中](https://community.openai.com/t/please-keep-chatgpt-and-codex-usage-limits-separate-in-december-2026/1411466)，用户呼吁该公司放弃拟议的整合，或者保证订阅者在新系统下不会获得更少的可使用容量。发起这场讨论的论坛成员化名为 Smalikou，他认为这两款产品应该保留独立的配额，并呼吁提高使用量计算方式的透明度。

他们写道：“ChatGPT 和 Codex 服务于不同的目的，它们的使用限制应该保持独立。”

另一位名为 PZA 的用户则呼吁提供更详细的使用报告，包括按产品、模型和任务划分的消耗明细。

他们[写道](https://community.openai.com/t/please-keep-chatgpt-and-codex-usage-limits-separate-in-december-2026/1411466/2)：“如果 OpenAI 决定无论如何都要将它们合并，那么在更改生效之前，必须提供一个实时的使用仪表板。它应该显示剩余配额、重置时间以及按产品、模型和任务分类的消耗量。如果没有这种透明度，我将认为这一更改是对我付费计划的降级，并会重新考虑续订。”

> “如果没有这种透明度，我将认为这一更改是对我付费计划的降级，并会重新考虑续订。”

巧合的是，OpenAI 已经确认，订阅用户将能够在 ChatGPT 的设置中查看他们合并后的剩余配额和重置时间，但尚未明确其中将包含何种详细程度。

这些担忧出现的几天前，OpenAI 刚刚撤销了一项[将其 200 美元 Pro 订阅的使用限制减半的争议性决定](https://thenewstack.io/openai-halves-200-plan/)。10月29日，该公司确认取消 Pro 200 的削减计划，为已经转移到较低限制的订阅者恢复较高的 Work 和 Codex 配额，同时将 Pro 100、Pro 500 和 Business Premium 订阅者的配额翻倍。

OpenAI 的 ChatGPT 和 Codex 负责人 [Tibo Sottiaux](https://www.linkedin.com/in/thibault-sottiaux-27195366) 承认了围绕拟议削减额度的批评，他在 [X 上发文](https://x.com/thsottiaux/status/2115850175868727621)称，该公司已经听取了订阅用户的反馈，并将保留现有的 Pro 200 配额。

他写道：“我们听取了你们的宝贵反馈，不会降低 Pro 200 的使用限制，因此你们的 Work 和 Codex 使用量将保持不变。”

然而，一位论坛参与者质疑，一旦 ChatGPT 对话开始消耗与 Codex 相同的配额，这些配额的增加能给订阅者带来多少好处。化名为 Zigg88 的用户指出，他们已经经常接近其每周的 Codex 限制。

他们[写道](https://community.openai.com/t/please-keep-chatgpt-and-codex-usage-limits-separate-in-december-2026/1411466/17)：“将资源分配翻倍，同时又扩大消耗它的事物数量，这并不一定会转化为更多可用的容量。”

其他人[表达了担忧](https://community.openai.com/t/why-shared-chatgpt-and-codex-limits-could-disrupt-research-code-review-and-continuous-development/1411856)，担心这会影响他们在依靠 Codex 进行软件开发的同时，使用 ChatGPT 进行研究和技术规划的能力。一位评论者认为，OpenAI 应该保留独立的配额，或者在新系统下保证同等的访问权限。

*The New Stack* 联系了 OpenAI，询问这些更改究竟会在 12 月的什么时候生效，以及新的合并配额是否会等同于现有的独立配额，还是会让一些订阅者的可用容量减少。该公司拒绝回答这些问题，而是重申了其最近对 Work 和 Codex 使用限制的提高，并引导我们查看其现有的文档。

目前，OpenAI 表示预计大多数用户遇到配额重置的频率不会比现在更高。然而，在没有公布新的 Token 配额或解释它们与现有限制相比如何的情况下，订阅者很难知道这种安慰是否对他们适用。
