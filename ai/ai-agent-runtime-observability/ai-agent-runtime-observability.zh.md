**运行 OpenAI 网络安全评估的模型**从一个设计为隔离的环境中[突破到了公共互联网](https://thenewstack.io/openai-huggingface-sandbox-breach/)。通过内部注册表代理和缓存进行的包安装是唯一预期的网络路径。

这些模型在该代理中发现了一个以前未知的漏洞。它们升级了权限，横向移动到一个有互联网访问权限的节点，然后利用更多漏洞和被盗凭据入侵了 Hugging Face 的生产基础设施。

隔离政策规定公共互联网是禁区——但运行中的系统证明事实并非如此。

这不是一个缺乏监控的故事。OpenAI 表示其安全团队在内部检测到了异常活动。[Hugging Face 报告称](https://huggingface.co/blog/agent-intrusion-technical-timeline)，它将运行时信号和 SIEM 信号组合成了一个攻击信号，但该警报不够紧急，未能促使值班团队及时响应。

Hugging Face 的调查人员在多个信任边界恢复了大约 17,600 个智能体操作。信号是存在的。它们没有足够早地触发干预。

> “配置好的边界并不能证明运行时可以访问什么。”

[Anthropic 对 141,006 次网络安全评估运行的审查](https://www.anthropic.com/news/investigating-incidents-cybersecurity-evals)发现涉及 6 次运行的 3 起事件，揭示了一种不同的失效模式。这些模型之所以接触到真实系统，是因为评估环境具有意料之外的互联网访问权限。这是一个配置错误，而不是被利用的沙箱逃逸。

这些是能力评估，而不是正常的生产部署。两个组织都报告说，为了衡量底层网络能力，他们移除或减少了标准的部署防护措施。

但治理教训依然适用：配置好的边界并不能证明运行时可以访问什么。

## 为什么AI智能体改变了遏制问题

运行时检测和纵深防御并不新鲜。智能体改变了执行模型。

在固定的工作流程中，代码指定了中间步骤。而使用工具的智能体可以在运行时选择和修改这些步骤。它可以对结果做出反应，重试失败的路径，并将一个工具的输出用作另一个工具的输入。

这改变了必须被治理的内容。DNS 查找、包下载或凭据读取单独来看可能是无害的。但在正确的序列中，相同的事件可以形成从沙箱到生产系统的路径。

设计时治理设定了条件：隔离、身份、工具权限、策略和批准。运行时治理根据这些条件衡量发生的事情，并在两者出现分歧时更改系统状态。

可观测性并不能取代预防。它展示了预防何时不再符合现实。

治理框架已经反映了这一区别。对于高风险系统，[欧盟人工智能法案](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=celex%3A32024R1689)要求自动事件日志记录、能够检测异常并中断系统的人类监督，以及在其整个生命周期内的上市后监测。[NIST 的生成式 AI 框架](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence)同样呼吁进行部署后监测、升级和事件响应。

> “可观测性并不能取代预防。它展示了预防何时不再符合现实。”

这些框架确立了要求。智能体压缩了必须满足该要求的响应窗口。一项特定于部署的指标使其变得可见：

```

actions_before_containment = agent_action_rate x detection_to_containment_time

```

这并不衡量这些操作的严重性。它衡量在系统介入之前可以发生多少操作。

## 将遥测转化为治理的四个属性

答案不仅仅是更多的日志。运行时证据系统需要四个属性。

**覆盖度：** 改变权限或产生外部影响的转换是否被进行了检测？相关事件包括[智能体和运行身份](https://thenewstack.io/securing-autonomous-ai-agents/)、工具调用、进程执行、权限更改、凭据使用、网络目的地、包检索、资源更改和策略决策。日志量无法弥补盲目的信任边界。

> “答案不仅仅是更多的日志。日志量无法弥补盲目的信任边界。”

**关联性：** 是否可以将外部影响追溯到导致它的操作？证据应识别智能体运行、工具调用、策略决策和派生操作。没有进程、身份和网络证据的规划器跟踪显示的是请求，而不是其效果。没有智能体跟踪的进程和网络证据显示的是效果，而不是导致它的决策。

**及时性：** 系统能否在操作变得不可逆转之前进行干预？在高影响操作（如公共出口、凭据访问、代码执行和生产写入）之前放置同步门。流式分析处理仅在几个事件中变得危险的模式。然后，单独的响应服务可以暂停运行、隔离工作负载或撤销其凭据。

**可审计性：** 调查人员能否在不信任智能体陈述的情况下重现发现？我的[早期文章](https://thenewstack.io/agent-evidence-packet-analytics/)认为，基于数据库的观察应该与智能体的解释保持分离。同样的隔离也适用于此。智能体可能会解释其行为，但它的解释不是审计记录。

## 从证据到干预

遥测只有在连接到响应时才会变成遏制：

```

agent action + policy decision + infrastructure effect
                         |
                         v
               correlated evidence
                         |
                         v
                      response

```

智能体操作、策略决策和基础设施影响确定了尝试、允许和更改的内容。将它们关联起来可以将单独的事件变成证据。将该证据连接到响应可以将可观测性转化为遏制。

这些证据创造了其自身的分析工作负载。智能体运行、工具、身份、策略决策、进程和网络目的地都增加了维度。在分析之前删除这些维度可能会删除识别违规运行的信号。

此反馈循环中的证据来自两个仪器层，上面的覆盖列表跨越了这两者。智能体运行时发出运行身份、模型调用、工具调用和护栏检查。基础设施发出进程执行、凭据使用、网络目的地和资源更改。这两层都无法重构另一层。基础设施日志无法说明哪个运行或哪个工具调用打开了连接。智能体跟踪无法说明连接到达了哪里。

智能体层是[LLM 可观测性的领域](https://thenewstack.io/what-is-llm-observability-and-monitoring/)。Langfuse 将智能体采取的每一步记录为[类型化观察](https://langfuse.com/blog/2024-07-ai-agent-observability-with-langfuse)，包括智能体、工具、生成和护栏步骤，并区分智能体可用的工具和它调用的工具。这种区分支持对敏感工具使用和循环工具路径进行过滤，并对结果发出警报。跟踪上下文跨越服务边界并[通过 MCP 调用传播](https://thenewstack.io/mcp-ai-agents-api/)，因此一个跟踪可以跨越多服务智能体及其工具服务器。

[DKB](https://langfuse.com/users/dkb) 为大约 600 万银行客户运行一个助手，可以更改转账限额并阻止卡，客户确认每个操作。Langfuse 跟踪每次交互，自动筛选合规违规行为，并将标记的案例路由给人工审核。[Cresta](https://langfuse.com/users/cresta) 在 Go 智能体服务、Python 检索管道和工具执行服务之间传播跟踪上下文，因此一个跟踪涵盖整个调用树。

ClickStack 覆盖了基础设施层。它将 OpenTelemetry 日志、指标和跟踪作为宽事件收集在 ClickHouse 中，允许团队在实时检测和取证调查期间将高基数遥测与 SQL 关联起来。

这两层共享跟踪上下文。用 OpenTelemetry 进行检测的应用程序可以[将相同的跟踪导出到两者](https://langfuse.com/integrations/clickhouse/observability)，以便每个工具都可以识别相同的请求。日志和指标继续流向 ClickStack，SQL 在那里将它们与这些跟踪相关联。两者都将其数据存储在 ClickHouse 中。

> “治理不是政策文件。它是系统展示政策是否保持、解释未保持时发生的事情以及阻止后果蔓延的能力。”

Langfuse 和 ClickStack 互补了策略引擎、身份系统和执行机制。策略引擎评估允许的内容，身份系统确定谁或什么在行动，执行机制执行响应。这两个可观测性层将它们的信号与观察到的行为结合在一起，ClickHouse 作为关联和调查的分析基础。

该运行时治理循环应该通过四个测试：

1. 每个关键信任边界都有遥测覆盖。
2. 您可以将每个高影响操作从智能体身份和策略决策追溯到下游影响。
3. 证据及时到达策略门或有界停止路径，以防止或遏制不可逆的影响。
4. 审计记录保持独立于智能体的叙述。

治理不是政策文件。它是系统展示政策是否保持、解释未保持时发生的事情以及阻止后果蔓延的能力。
