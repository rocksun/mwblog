Anthropic 宣布将在新 Claude 模型生成的文本中嵌入隐形水印，包括通过其 API、编码工具和云合作伙伴输出的内容。对于开发者来说，这种标记提供了一种追踪 AI 生成文本或代码来源的方法，但尚不足以证明其确切来源。

Anthropic 在一份[支持文档](https://support.claude.com/en/articles/16266773-how-claude-marks-ai-generated-content)中阐述了该计划，称 2026 年 8 月 2 日或之后在欧盟推出的 Claude 模型将从发布之日起包含机器可读的标记。该公司也正在努力为旧模型增加支持。

这些标记将在支持 Claude 的产品中全球范围内应用，包括 Claude API、Claude Code、Claude Cowork 和 Claude Tag。当 AWS、Google Cloud 或 Microsoft Foundry 使用支持的模型时，通过这些平台生成的文本也将带有水印。由于该标记是在模型层面添加的，它会跟随输出进入基于 Claude 构建的应用程序中——这些应用程序已经在[重塑企业部署 AI 基础设施的方式](https://thenewstack.io/anthropic-mendral-cicd-acquihire/)——尽管 Anthropic 提醒称，某些平台和功能可能不支持所有类型的标记。

此项变更是在 8 月 2 日 [欧盟 AI 法案第 50 条透明度要求](https://artificialintelligenceact.eu/article/50/)生效后进行的，该法案要求生成式 AI 系统提供商使合成输出能以机器可读的格式被检测到。作为生成式 AI 模型和系统的提供商，Anthropic 签署了随附的《行为准则》。OpenAI、Google、Meta、Microsoft 和 Mistral 等其他模型提供商也承诺遵守该准则。

然而，Anthropic 处理文本和文件的方式有所不同。文本中隐藏着嵌入在文字本身的水印，而 SVG、PNG 和 JPG 等受支持的文件则使用 C2PA 标准进行数字签名。文件元数据可以显示 Claude 是否处理过该资产，以及元数据是否被篡改。

“由于水印是文本的一部分，它在被复制粘贴到其他地方时会随文本一起移动，并可能在某些编辑过程中保留下来，”Anthropic 表示。

> “由于水印是文本的一部分，它在被复制粘贴到其他地方时会随文本一起移动，并可能在某些编辑过程中保留下来。”

## Token 级水印的工作原理

Anthropic 尚未解释其文本水印的工作原理，也未说明 Claude 是否使用 KGW、语义版本或其他方法。该公司也未分享任何显示水印是否会影响延迟或增加推理成本的数据——对于已经在[应对代理式 AI 工作流隐藏成本](https://thenewstack.io/agentic-ai-token-costs/)的团队来说，这很重要。

AI 检测公司 GPTZero 的 CTO 兼联合创始人 [Alex Cui](https://www.linkedin.com/in/alex-cui-caltech/) 在 X 上的一篇[技术说明](https://x.com/alexcdot/status/2087078010524406137)中写道，运行在流式前沿模型上且速度足够快的水印系统通常遵循相同的通用方法。一种名为 KGW 的技术会改变模型在选择下一个 Token 时使用的概率。

语言模型通常会为下一个可能出现的每个 Token 计算一个概率。在一个简化的水印系统中，密钥和前面的 Token 用于生成哈希值，将候选 Token 分为两组（通常描述为绿色和红色）。然后，模型会稍微增加选择其中一个绿色 Token 的概率。

具有相同密钥的检测器可以使用前面的文本来重构每个位置优先选择的 Token。包含异常多此类选择的段落可能带有水印。

Cui 写道，更先进的方法可以从附近文本的含义中导出水印，而不是仅仅依靠精确的 Token 序列，这可能有助于信号在某些释义中存活，因为替换单词并不总会改变周围的上下文。

“他们的水印需要逐个 Token 地工作，因为他们是将文本流式传输给用户的，”Cui 写道。“许多水印方法一次规划句子或段落，或者在文本完全写完后修改文本，以使水印对释义更具鲁棒性。”

Anthropic 尚未确认 Claude 是否使用这些方法中的任何一种，但流式传输限制了可用的技术，因为模型必须在生成响应时添加信号，而不是事后重写完整的段落。

## 代码抵制隐形标记

代码提出了一个不同的问题，因为模型有效的选择较少。单词通常可以互换或句子可以重写而不改变其含义，但看似微小的改动可能会破坏可运行的代码。随着 [AI 编码时代的成熟](https://thenewstack.io/microsoft-copilot-token-budgets/)，越来越多的生产代码流经模型辅助的流水线，这一挑战愈发严峻。

“有些文本，比如代码，不能随意更改；否则代码会崩溃，”Cui 写道。“在这些情况下，水印需要选择性地更改文本中可以容忍同义词的部分，”例如变量名。

代码也可能难以通过正常的开发工作流进行追踪。Anthropic 尚未发布测试结果来显示其水印在这些更改后的存活率，因此团队目前还不知道 Claude 生成的补丁在经过 Pull Request 后是否仍然可检测。

> “在我的测试中，水印在激烈的释义攻击下无法存活，特别是当你结合词汇选择和语法攻击时。”

## 流水线会静默擦除水印

当应用程序在向用户显示或提交到存储库之前更改 Claude 的输出时，也会出现同样的问题。使用另一个模型进行总结、翻译、将其拆分为较小的部分、将其转换为结构化数据或将其与数据库内容混合，都可能使水印更难被检测到。

Anthropic 承认了这一局限性。编辑、释义、翻译或将响应与其他文本合并可能会削弱或删除水印，而短摘录可能不包含足够的信号来检测。

Cui 写道，意志坚定的用户可以通过改变段落的词汇和结构来攻击水印。

“在我的测试中，水印在激烈的释义攻击下无法存活，特别是当你结合词汇选择和语法攻击时，”他写道。Cui 补充说，他测试的免费释义工具能够绕过 Google DeepMind 的 SynthID 文本水印。

研究支持这些担忧。《“Watermarks in the Sand”》论文发现，在定义的假设下，攻击者可以在不严重损害内容质量的情况下删除水印。水印的缺失并不能证明 Claude 没有参与内容的创作。响应可能来自旧模型，可能太短而无法携带可检测信号，或者可能在应用程序流水线中的某处被更改。它也可能通过了不支持该类型标记的平台或功能。

发现水印也不能证明作者身份。Claude 可能校对、翻译或重新格式化了由人撰写的材料。Anthropic 表示，检测到的标记仅意味着内容“可能由 Claude 处理过”，而不是 Claude 创建了基础作品。

> “如果 Anthropic 公开水印检测器，我认为他们就等于击败了自己的水印。人们可以通过针对 Anthropic 进行测试来找到可靠的水印移除策略。”

## 检测带来新风险

Anthropic 计划为用户和第三方提供检测其标记的方法，但尚未说明这将采取本地工具、检测 API 还是仅限于选定组织的访问权限的形式。公开的检测器更容易让开发者添加到他们的应用程序中，但它也会让试图删除水印的人能够不断编辑和检查文本，直到信号消失。

“如果 Anthropic 公开水印检测器，我认为他们就等于击败了自己的水印，”Cui 写道。“人们可以通过针对 Anthropic 进行测试来找到可靠的水印移除策略。”

水印背后的密钥带来了另一个挑战。泄露的密钥可能使删除标记或在非 Claude 生成的文本中伪造标记变得更容易。这种场景呼应了[当来源证明被变成伪装时发生的情况](https://thenewstack.io/npm-supply-chain-worm-attack/)——一个本应增加信任的信任信号反而成为了攻击面。

“为了避免由此产生巨大的破坏，你需要轮换几个密钥，”Cui 写道。

密钥轮换将要求检测器识别使用当前和已停用密钥创建的标记，包括嵌入在几个月或几年前生成的内容中的标记。Anthropic 尚未解释它计划如何处理这些历史记录。

## 水印不能替代真正的来源追踪

对于开发者来说，Claude 的水印最好被视为另一条线索，而不是审计日志或来源追踪的替代品。需要展示工件来源的应用程序可以记录模型 ID、提示词版本、响应时间和原始输出的哈希值，然后记录在它到达用户或提交到存储库之前所做的任何更改。

水印公告发布之际，Anthropic 正在处理有关其模型在野外表现的更深层次问题。最近的事件[暴露了实验室安全评估与现实世界控制之间的差距](https://thenewstack.io/anthropic-claude-containment-failure/)，该公司已[公开支持要求最强大的 AI 实验室放慢速度的呼吁](https://thenewstack.io/ai-pause-framework-letter/)。水印符合这种立场——这是一种透明度机制而非安全保障——但其实际价值取决于 Anthropic 尚未分享的技术细节。

Anthropic 告诉客户自行确定第 50 条如何适用于其自身产品，并表示会有更多的技术文档发布。但在 Anthropic 分享这些细节之前，团队不知道他们将如何检测标记、密钥轮换将如何工作，或者水印在代码和应用程序输出的常见更改下表现如何。
