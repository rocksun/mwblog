本文探讨了如何通过Open Mainframe Project及Zowe框架，将大型机从孤立的遗留系统转变为现代数字化企业的核心战略平台。通过集成API、DevOps和现代化协作工具，大型机能更好地融入云原生架构，打破技术与组织壁垒，提升企业整体的运营韧性与创新能力。

> 译自：[The open mainframe: the keystone of the end-to-end digital enterprise](https://thenewstack.io/open-mainframe-keystone-enterprise/)
> 
> 作者：Jason Bloomberg

在[本系列的第一篇文章](https://thenewstack.io/open-mainframe-enterprise-modernization/)中，我讨论了[Open Mainframe Project](https://openmainframeproject.org/) (OMP) 及其开源框架 [Zowe](https://www.zowe.org/) 如何推动现代化——不仅仅是大型机本身的现代化，更是依赖它们的企业的现代化。

有了 OMP，大型机从创新的束缚转变为创新的战略平台。现在，大型机在各种现代计划中发挥着核心作用，包括 AI、云原生、自动化以及其他战略性的数字化工作。

然而，要将大型机转型为更具战略意义的创新平台，需要的不仅仅是开源工具及其背后的社区。

> “有了 OMP，大型机从创新的束缚转变为创新的战略平台。”

开放大型机更宏大的故事在于它所促进的深度架构变革。利用开放大型机功能的组织发现，他们可以将大型机重新定位在企业架构的中心。

与其将大型机视为具有独特需求的孤立平台，依赖大型机的企业可以将该平台确立为端到端数字工作流的一流参与者——这些工作流利用了现代云原生架构、自动化和以 AI 为中心的基础设施。

## 重塑大型机

依赖大型机的企业——例如银行、保险公司、航空公司和零售商——早已认识到大型机是一个完全现代化的平台。

今天的大型机支持现代编程语言、操作系统和[云原生基础设施](https://thenewstack.io/why-cloud-native-infrastructure-is-non-negotiable-for-genai/)。

然而，即使在现代环境中，该平台仍然是主要的记录系统：作为组织核心的关键任务数据和核心交易的可信之家。

这种关于大型机的传统视角可以追溯到大型机充当“主机”的分时系统时代——这种模式在今天会导致脆弱的集成、重复的逻辑和运营盲点。

大型机上的开放功能颠覆了这种过时的观点。借助 Zowe 等开源框架，组织可以将大型机连接到现代工作流中，而不是将其视为一个孤立的记录系统。

换句话说，大型机不再仅仅是一个主机——它成为现代混合 IT 环境所享有的开发、自动化和运营实践中不可或缺的一部分。

> “大型机不再仅仅是一个主机——它成为现代混合 IT 环境所享有的开发、自动化和运营实践中不可或缺的一部分。”

此外，将大型机作为企业架构中的中央工作流协调器，使架构师和开发人员能够重新设计企业工作流以纳入该平台。

结果，大型机在交易流、数据处理（平台内外）以及 ERP 等企业应用系统中变得在架构上处于核心地位。

这种架构方法通过将大型机众所周知的可靠性、性能和治理优势扩展到跨组织工作流中，可以为企业带来实际利益。

各种企业系统之间更紧密的集成是这一工作带来的战术性好处。更具战略意义的是，组织可以实施更连贯的架构，将其最高价值的系统直接嵌入到数字运营流程中。

## 作为全面集成 DevOps 参与者的大型机

将大型机定位为企业架构的基石，需要在所有架构层面上进行转变，包括软件开发和 DevOps，而 Zowe 在这些领域产生了重大影响。

Zowe 使大型机开发人员能够通过 API 访问大型机服务，将其[集成到 CI/CD 流水线中](https://thenewstack.io/qcon-chat-is-agentic-ai-killing-continuous-integration/)，并使用跨分布式和云原生环境的团队所熟悉的工具进行管理。

通过 API 公开大型机功能并将其集成到现代 DevOps 工具中，大型机开发变得与组织内任何其他开发一样通用、可自动化且可衡量。

> “通过 API 公开大型机功能并将其集成到现代 DevOps 工具中，大型机开发变得与组织内任何其他开发一样通用、可自动化且可衡量。”

开发团队可以与其他云原生服务一起测试、部署和监控大型机工作负载，从而在整个 IT 领域获得对系统性能和业务成果的统一视图。

这种[统一的可观测性](https://thenewstack.io/why-consolidating-observability-tools-is-a-smart-move/)所提供的价值远不止于改进运营。借助开放大型机功能，企业可以更好地优化工作负载、合理化 IT 投资，并将这些投资与战略业务目标相一致。

结果，大型机失去了其作为基于主机的成本中心的地位。它成为 IT 资产中关键任务的一部分——其价值不仅可以通过软件本身来衡量，还可以通过大型机对组织战略目标的更广泛影响来衡量。

## 打破技术和人员孤岛

利用各种 OMP 项目将大型机置于现代企业工作流的中心，显然是打破技术孤岛的一个例子——但这种打破孤岛的故事也延伸到了组织孤岛。

传统的大型机环境需要专业技能，通常来自拥有数十年经验的资深大型机人员。这种孤立的组织模型会导致瓶颈、协作受限，以及随着经验丰富的员工退休而导致部落知识的流失。

为了应对这一挑战，Zowe 将现代开发范式引入了大型机世界，包括基于 Git 的工作流、RESTful API 和现代 IDE。

对于 Broadcom 而言，这一转变与 [Beyond Code](https://www.broadcom.com/solutions/mainframe/go-beyond-code) 相一致：一种将现代实践与大型机组织长期所需的技能发展相结合的方法。

大型机专业知识仍然是必要的，但不再是资深大型机人员的专属领域。相反，Zowe 框架使已经熟悉现代工具和实践的专业人员更容易进行大型机工作。

因此，企业可以通过长期维持和发展员工的技术专长来实现更强的员工韧性。

## Intellyx 观点

OMP 的故事看起来可能是单向的——将现代实践引入大型机——但另一个方向同样重要。

长期以来，大型机世界因其卓越的运营而享有当之无愧的声誉，这部分是因为技术的稳健性，但也同样是因为维护它的人员的卓越运营。

Zowe 的开放大型机功能使依赖大型机的企业能够将这种卓越扩展到 IT 资产的其他部分。通过建立连贯的架构基础，企业可以在组织的所有平台上实现更高的韧性和改进的性能。

实现开放、集成和可衡量的流程，使企业能够充分利用其所有技术投资的价值，同时为未来的持续创新做好准备。

通过关注[员工韧性](https://news.broadcom.com/mainframe-software/mainframe-know-how-sustain-a-resilient-workforce)、运营成熟度和可衡量的业务成果，企业可以实现超越单纯软件交付的大型机愿景——迈向现代、可持续的架构，将大型机转型为整个企业的战略资产。
