**在周二的 DevDay 活动中，OpenAI 推出了 Dots**：基于 GPT-6 Astra 构建的持久型智能体，它们运行在自己的云计算机上，使用自己的浏览器，并能够通过 OpenAI 的插件生态系统访问 4,000 多个应用程序。

与大多数等待下一个 prompt 的智能体不同，Dot 在你离开时会继续工作。它可以同时处理几个项目，并在 ChatGPT、Slack 和 Microsoft Teams 之间传递它所知道的信息。你还可以打开它的云计算机来查看它在做什么，或者授权它直接从你的笔记本电脑上进行工作。

> 与大多数等待下一个 prompt 的智能体不同，Dot 在你离开时会继续工作。

## 从反馈到 Pull Request

OpenAI 的开发者示例展示了 Dot 承担了从识别问题到交付修复之间的大部分工作。它可以监控客户反馈以查找重复出现的请求，规划较小的改进和错误修复，构建和测试更改，并返回带有显示更改内容的视频的已完成 pull request。然后，开发人员可以审查这些工作，同时专注于更大的功能。

## 只读的主动研究

一个全天候无人值守工作的智能体需要对其能做的事情进行限制，OpenAI 将寻找工作与对其实施操作进行了区分。当用户没有积极与 Dot 合作时，它可以执行 OpenAI 所称的“主动研究”，通过连接的应用程序寻找提供帮助的方法。但这种访问是只读的，这意味着 Dot 无法发送消息、更改应用程序内容或控制浏览器或计算机。

可能影响用户帐户或共享信息的操纵会通过一个单独的“自动审查”步骤，该步骤会根据用户的指令、OpenAI 的安全要求以及用户设置的任何自定义规则对其进行检查。这些规则可以允许特定操作自行进行、要求批准或阻止它们，而某些敏感任务（例如更改密码）始终由用户掌控。

> 一个全天候无人值守工作的智能体需要对其能做的事情进行限制，OpenAI 的方法是将寻找工作与对其实施操作分开。

OpenAI 承诺 Dots 还包括防范恶意指令的安全防护措施——对于一个读取来自数千个连接应用程序内容的智能体来说，这是一个真正的担忧，同时还配备了一个监控系统，当检测到安全问题时可以暂停或停止 Dot。用户可以在活动视图中跟踪 Dot 所做的所有事情（包括后台工作），并从那里重定向它。OpenAI 提醒说，Dots 仍然会犯错误，建议审查重要的工作。

用户的电脑与 Dot 的环境保持隔离，除非他们选择连接它，并且在支持的网站上，Dot 可以使用保存的密码登录，而不会向模型泄露这些密码。OpenAI 表示，默认情况下，它不会使用来自 Business、Enterprise 或 Education 工作区的内容来改进其模型；个人计划用户可以控制其 Dots 的对话和工作是否用于训练，并且它不会直接对主动研究或 Dot 为自己编写的笔记进行训练，尽管根据用户的设置，如果它们为符合条件的对话或任务提供信息，则可能会使用其中的信息。

## 专业版 Dots 与 Agent 365

OpenAI 还预览了专业版 Dots，组织可以为其配置自己的身份、凭据、IT 配置的硬件和记录系统的访问权限，以便每个智能体拥有定义的的工作流程，而不是协助单个员工。

该公司已在采购、发票处理、电子邮件营销、客户支持和商业合同方面在内部测试了这种方法，并计划通过企业试点开始外部部署，在这些试点中，OpenAI 工程师与客户合作定义每个 Dot 的职责、工具访问权限和审查点。

OpenAI 还与 Microsoft 合作，将专业版 Dots 与 Agent 365 中的治理和安全控制集成在一起，以便管理员可以通过他们已经在运行的工具来管理它们。

## 按智能体容量定价 Dots

Dots 目前正在向符合市场条件的 ChatGPT Pro 和 Business Premium 用户推出，这些计划中包含一个 Dot，无需额外费用。企业客户（包括 Edu 和 Healthcare）在工作区管理员启用后即可使用该测试版。设置在 ChatGPT 桌面应用程序或桌面浏览器中进行，之后也可以从移动应用程序访问 Dot，OpenAI 表示文本消息支持即将推出。

与 Dot 的对话不计入 ChatGPT 的使用限制，但它在 Codex 或 ChatGPT Work 中启动或管理的任务照常消耗这些产品的限制。计划包括深度工作的额度，并在发布后的第一个月内提供扩展限制。

OpenAI 计划让客户添加更多的 Dots，并提高 Dot 的速度或每月可以承接的工作量。
