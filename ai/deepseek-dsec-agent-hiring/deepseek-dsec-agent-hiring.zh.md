单一 DeepSeek 集群目前已能并行运行数十万个 AI Agent 沙箱。随着这一数字及其背后的训练、评估及其他后端工作负载持续攀升，DeepSeek 正在扩充人员以应对这一挑战。

今年 3 月加入 DeepSeek 并负责 Harness 团队（该团队负责运行和评估 Agent 的基础设施与环境）的 [Cui Tianyi](https://www.linkedin.com/in/tianyicui/) 在 [X](https://x.com/tianyi) 上发文宣布，DeepSeek 将提供约 150 个工程岗位。此次招聘重点集中在服务端工程和 Agent 弹性计算，而非 AI 研究领域。工作范围涵盖操作系统、虚拟化、网络、存储、调度以及协调这些资源的控制平面服务。

Cui 表示，随着工作负载的增长，DeepSeek 现有的后端系统将需要升级、维护和重写。处于这一扩展挑战核心的系统之一是 DeepSeek 弹性计算（DeepSeek Elastic Compute，简称 DSec），这是 DeepSeek 构建的用于在后训练和评估阶段执行 Agent 工作负载的沙箱基础设施。

## 四种沙箱，一套 SDK

Agent 工作负载需要的不仅仅是用于推理的 GPU，每个 Agent 还需要一个独立的隔离环境来运行代码、调用工具、修改文件并收集结果。

DSec 通过同一套 Python SDK 支持四种类型的环境。简单的函数调用会被发送到预热容器中，而 Docker 兼容容器则处理需要持久化环境的任务。当需要更强的隔离性时，DeepSeek 使用 Firecracker microVMs；对于需要完整客户操作系统的任务，则使用 QEMU 虚拟机。

这种范围意味着同一套基础设施可以处理从简单的工具调用到需要整个操作系统的软件工程任务。随着 Agent 从演示阶段走向生产环境，整个行业都在面临类似的挑战。例如，OpenAI 最近[设计了定制芯片](https://thenewstack.io/openai-jalapeno-inference-chip/)，专门用于解决 Agent 工作负载带来的计算压力；DeepSeek 也在 8 月[开源了其 Agent 框架](https://thenewstack.io/deepseek-harness-open-source-plugins/)。

## Agent 环境的惰性加载

每个沙箱都需要自己的环境，但将完整的容器或虚拟机镜像复制到每台主机上会消耗大量的存储和网络带宽，并增加启动时间。DeepSeek 通过将 DSec 与 3FS（其最初为其 AI 基础设施构建的分布式文件系统）连接，并将容器基础镜像和文件系统提交作为由 3FS 支持的只读层来解决这一问题。

元数据保持在本地，但底层数据块仅在实际需要时才被获取。MicroVMs 使用类似的设置，通过 3FS 共享它们的只读基础层，而来自各个沙箱的写入则保存在本地的写时复制（copy-on-write）层中。

[DeepSeek 表示，DSec 减少了虚拟化环境中重复的页缓存使用](https://api-docs.deepseek.com/news/news260424/)，并回收内存以允许安全的超额认购，同时对容器运行时的修改减少了每个沙箱的 CPU 开销。

该团队还必须处理容器运行时内部的自旋锁竞争问题。在小规模情况下，在此消耗的 CPU 时间几乎可以忽略不计。但在大规模环境下，这限制了这些环境在每台主机上的部署密度。

## 当重放干扰训练时

在强化学习和其他后训练工作负载期间，可能会同时运行大量的 Agent 部署任务，且计算资源被重新分配时，任务可能会中断。重新开始会浪费 Agent 已经完成的所有工作，但从中断处恢复并不像重新执行其之前的命令那么简单。

其中一些命令可能已经更改了文件或以其他方式改变了环境，因此再次运行它们可能会产生不同的结果，或使训练轨迹处于错误的状态。DSec 通过全局有序的轨迹日志来避免这种情况，该日志记录了命令及其结果。

当部署任务恢复时，DSec 可以使用这些记录的结果快进完成的工作，而不是第二次执行这些命令。这降低了数千次训练和评估运行中因中断产生的成本，同时相同的日志保留了每个沙箱如何变化的记录，并允许重放之前的会话。

## 需求是工程师，而非研究人员

这 150 个左右的空缺职位涵盖了 DeepSeek 的后端，包括 Agent 弹性计算背后的底层系统工作，以及支持其模型和 Agent 的服务。

[DeepSeek 在 6 月曾表示](https://www.reuters.com/world/asia-pacific/chinas-deepseek-plans-least-double-staff-all-departments-2026-06-25/)，计划将每个部门的规模至少扩大一倍，但这一轮招聘明显倾向于模型底层的系统，而不是模型本身。DSec 正是这项工作的一部分，随着数十万个沙箱同时运行，从任务调度方式到中断后的恢复方式，一切都面临着巨大的压力。
