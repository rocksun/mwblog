本文对比了Anthropic的Claude合并版界面与OpenAI的ChatGPT工作模式。经过三项开发者实际任务测试，两者准确率相当，但ChatGPT速度更快、Token消耗更少，而Claude则凭借更详尽的上下文、背景说明和严谨性胜出。

> 译自：[Claude's merged chat and Cowork vs. ChatGPT's Work mode: ChatGPT is faster, Claude is more thorough](https://thenewstack.io/claude-cowork-vs-chatgpt-work-benchmark/)
> 
> 作者：Jessica Wachtel

当 Anthropic 上周将 [Claude 聊天与 Cowork 合并](https://thenewstack.io/anthropic-claude-unified-interface/) 到一个单一界面中时，它省去了用户在选择哪种模式时日益显得多余的决策过程。

现在，要同时使用这两个工具，只需提出一个问题，然后在同一线程中交办一个多步骤任务，Claude 就会进行路由。Anthropic 进行此更新是因为它表示客户经常难以在正确的任务中选择正确的标签页，因此合并后的应用现在会自行路由每个请求，而不是让你选择模式——目前，统一体验首先向 Pro 和 Max 订阅者推出，免费版和团队版将随后推出。

但这并不新鲜。OpenAI 自今年夏天早些时候以来就提供过同样的承诺。[OpenAI 在 7 月 9 日推出了工作模式（Work mode）](https://thenewstack.io/openai-codex-work-atlas/) 以及聊天功能，随后在次月逐步淘汰了较旧的独立代理模式（Agent mode）。工作模式是一个带有浏览器、代码执行和文件输出的沙盒环境，位于同一窗口中的聊天开关旁边——尽管评测人员指出，它还不能像代理模式那样在任务进行中将实时登录的浏览器会话交还给用户（例如用于登录或支付）。OpenAI 在其 Codex 编码代理的基础上构建了工作模式，此前 OpenAI 报告称，Codex 每周 500 万用户中大约有五分之一是非开发人员——据称这一群体的增长速度是开发人员的三倍。

随着 OpenAI 和 Anthropic 越来越接近功能对等，准确性、可靠性和 Token 使用量变得更加重要。有什么比进行头对头测试更好的方法来找出哪个工具更好呢？

## 测试

我进行了三项测试，涵盖了实际开发工作的不同领域。

* **API 研究** - 查找四个真实的开发者 API，并以表格形式列出其文档记录的速率限制、是否存在免费层以及当前的版本标识符。我在同一天对照供应商的文档检查了答案。
* **根据规范构建** - 根据具有严格边界情况的规范编写一个小型命令行持续时间解析器。我用一个包含 16 个隐藏用例的测试套件运行了每个应用的代码。
* **任务交接** - 询问两个堆栈跟踪中的哪一个指示了竞态条件，然后在同一线程中交接一项真实工作：从 Google Drive 拉取日志文件，计算每个端点的延迟百分位数和错误率，并交付带有图表的电子表格。我生成了日志数据，所以我提前知道了每个数字。

我记录了每次测试的 Token 成本和时间，并为有兴趣重复这项工作的人提供了提示词。

### API 研究

*提示词：研究这四个开发者 API 当前的公开文档，并为我构建一个表格，每个 API 一行，包含以下列：经过身份验证请求的记录速率限制、是否存在免费层（是/否），以及文档中显示的当前 API 版本标识符或日期。API：GitHub REST API、Stripe API、Twilio Messaging API、OpenAI API。列出你为每一行使用的文档页面。*

Claude 和 ChatGPT 在十二个评分字段上都回答正确，但 Claude 更全面。它包括了 GitHub 对 Actions Token 的单独限制、Twilio 的队列窗口以及 OpenAI 的层级阈值，此外还附带了一条关于它无法访问的一个页面的说明。

ChatGPT 在工作模式下于 1 分 17 秒内完成，并输出了 649 个 Token。Claude 花费了 1 分 44 秒，输出了 1,042 个 Token，阅读了八个页面，列出了九个来源，并主动提出将表格导出为电子表格。Claude 输出的 Token 数量接近两倍，花费的时间也更长，但在这种情况下，由于增加了详细信息，这是值得的。

### 根据规范构建

*提示词：*  
*构建下面规范中描述的命令行工具。交付一个名为 `durparse.py` 的单文件，它遵循所有规则。在返回之前自己测试一下。在你的回复中显示完整的最终代码。（后接规范：一个带有单位 d/h/m/s 的持续时间解析器，最大的在前，每个单位一个，允许小数，纯数字为秒，其余所有返回 None。）*

两个应用都返回了一个 `durparse.py` 文件，通过了所有 16 个隐藏测试，包括各种陷阱。这些陷阱包括单位顺序错乱、重复单位、没有单位的尾随数字和负值。包含 517 个 Token 的规范被发送给双方。ChatGPT 在 1 分 17 秒内完成，输出了 769 个 Token。Claude 花费了 1 分 45 秒，输出了 989 个 Token。Claude 报告在返回文件之前运行了 35 个它自己的测试用例。两者都提供了下载链接并在回复中显示了代码。

代码几乎完全相同，两者都使用了精确算术和固定顺序的正则表达式。Claude 指出了一个规范从未解决的判断问题：将 0.5 秒向上舍入是一种选择，而 Python 内置的 round 函数走向相反。ChatGPT 仅报告其测试通过。再一次，Claude 只是稍微更全面一些。

### 任务交接

*提示词：*  
*这两个堆栈跟踪中哪一个指向竞态条件，并用一句话说明原因？（带有两个跟踪）然后：现在从我的 Google Drive 中获取文件 api_logs.csv（列：time, endpoint, status, latency_ms），并生成一个可下载的电子表格，每个端点一行，显示请求计数、p50、p95 和 p99 延迟（以毫秒为单位），以及错误率（状态为 500 或以上的请求百分比）。添加一个按端点划分的 p95 延迟柱状图。同时在你的回复中显示表格。*

我用关于堆栈跟踪的问题（135 个 Token）在普通聊天中启动了每个线程。两者都在几秒钟内正确回答：跟踪 B，即在迭代过程中大小发生变化的字典。ChatGPT 花费了大约 10 秒和 48 个输出 Token。Claude 花费了 25 秒左右（118 个 Token），并添加了一个警告：如果循环体本身编辑字典，即使没有线程也会发生相同的错误。然后，在不切换模式的情况下，我交接了日志分析任务。

Claude 拉取了文件，计算了表格，并在大约 4 分钟内生成了一个带有 p95 柱状图的 .xlsx 文件，输出了 319 个 Token。ChatGPT 在 28 秒内生成了相同的电子表格和图表，使用了 467 个输出 Token。双方的所有 30 个数字都与我的基准真相相符。Claude 还命名了它的百分位数方法（线性插值），并指出如果我在 Google Sheets 中重新计算，数字将完全吻合。ChatGPT 给出了相同正确的表格，但没有提供像 Claude 那样多的细节。

## 结果

| **测试** | **ChatGPT (工作模式)** | **Claude (合并应用)** |
| --- | --- | --- |
| API 研究 | 12/12, 1:17, 125 输入 / 649 输出 | 12/12, 1:44, 125 输入 / 1,042 输出 |
| 根据规范构建 | 16/16 测试, 1:17, 517 输入 / 769 输出 | 16/16 测试, 1:45, 517 输入 / 989 输出 |
| 交接，问题 | 正确, ~10 秒, 135 输入 / 48 输出 | 正确, ~25 秒, 135 输入 / 118 输出 |
| 交接，任务 | 30/30, 28 秒活跃, 133 输入 / 467 输出 | 30/30, ~4 分钟, 133 输入 / 319 输出 |
| 总 Token（可见） | 910 输入 / 1,933 输出 | 910 输入 / 2,468 输出 |

Claude 和 ChatGPT 的准确性不相上下。每一个字段、每一个测试用例、每一个数字在双方都完全吻合，并且两者都引用了真实的文档。

区别在于速度和答案的详细程度。ChatGPT 在每项任务上都更快，产生的可见输出 Token 为 1,933 个，而 Claude 为 2,468 个。Claude 的部分额外输出是填充内容，但并非全部。它添加了提示词未要求的上下文，为其数字背后的百分位数方法命名，并指出了规范留下的两个判断问题。ChatGPT 给出了相同的正确答案，但上下文较少。

### 我怎么看？

我会选择 Claude，原因如下。在时间方面，ChatGPT 赢得了每一项任务，但在简短任务上的差距只是几秒钟（1:17 对 1:44，1:17 对 1:45），没有明显差异。在 Token 方面，ChatGPT 使用的输出比 Claude 少大约 22%，这是积极的，但考虑到细节/上下文的重要性，这就另当别论了。

在细节方面，Claude 在所有三项测试中都提供了更有意义的细节。这包括额外的 API 上下文、舍入判断问题和百分位数方法。在当今 AI 可能会凭空捏造的世界里，细节至关重要。
