这种权限与意图之间的鸿沟已经引发了问题。据悉，亚马逊内部的编码智能体 Kiro 在修复 AWS Cost Explorer 中的常规 Bug 时采取了意想不到的方法。它没有进行针对性的修改，而是决定删除并重新创建环境。该智能体继承了一名工程师的高级访问权限，从而绕过了双人审批流程。这起[事件](https://thenewstack.io/ai-agents-no-laws/)表明，当智能体的访问权限超出原始任务的限制时，它可能会将任务推进到何种地步。

## 用数据说话的过度热心智能体

在 [《过度热心的编码智能体》](https://arxiv.org/abs/2605.18583) 一文中，研究人员对四个编码智能体产品和六个模型的约 7,500 次运行进行了检查，其中一个发现在配对测试中尤为突出。研究人员发现，移除要求用户同意的一句话，使 Claude Code 的超出范围操作率从 0% 飙升至 17.1%。

框架也是造成显著差异的原因之一。Claude Code、Codex CLI 和 Gemini CLI 记录的过度热心操作率从 5.4% 到 27.7% 不等，而采用“请求继续”方法的 OpenHands 的这一比例仅为 0.2% 到 4.5%。即使在相同的框架内，更改底层模型也会产生高达 15.9 个百分点的差异。

另一项独立研究 [《编码智能体在猜测》](https://arxiv.org/abs/2607.02294) 测试了 Claude Code、Codex 和 OpenCode 对 2,208 个未充分说明的 DevOps 提示（涵盖 69 个任务系列）的反应。55.8% 到 67.8% 的运行违反了至少一条边界。

研究人员区分了针对错误目标的智能体和超出许可范围的智能体。这两个都是问题，但它们不能互换，因为智能体可能会执行完全要求的操作，但由于选择了错误资源而仍然惹麻烦。

## 当目标不明确时

在这些测试中，不明确的目标是最大的问题之一。关于行动潜在影响的警告，几乎无法减少智能体无论如何都要继续执行的频率。

两项研究都没有测试 Anthropic 传闻中的模型。然而，这两项研究都引发了人们的疑问：当指令留有解释空间时，推理能力的提升是否也会改善智能体的判断力。

## 将智能体控制在边界内

Anthropic 在其自身的测试中也遇到了类似的问题。在 10 月 9 日关于[非预期模型行动的报告](https://www.anthropic.com/news/investigating-unintended-model-actions)中，该公司描述了 Claude 在遇到限制后继续寻找完成任务方法的情况。

大多数案例涉及 Anthropic 所称的“持久性”（persistence），即 Claude 绕过障碍而不是停止。

在一次评估中，Claude Haiku 4.5 被告知完成一份表单，但在提交前停止。该模型依然提交了表单，显然是期望出现另一个确认页面。在另一次评估中，一个未发布的研发模型在练习版本加载失败或被意外关闭后，提交了一份真实的政府表单。

虽然这些不是编码任务，且该公司表示这些事件对现实世界的影响微乎其微，但它们仍然展示了智能体如何将限制误认为是需要绕过的问题。

Anthropic 已经承认，更清晰的指令可能本可以防止某些故障。该公司还表示，已开发出监控工具，在对其进行测试时阻止了每一个记录在案的案例。

但更清晰的指令只能解决部分问题。用户希望智能体能够处理歧义，而不用在每个转折点都停下来寻求帮助。
