**GitHub 正在经历空前绝后的需求**，并正在更新其核心基础设施以保持步伐。

在 8 月份，GitHub 表示它看到了 [每月 29 亿次提交](https://thenewstack.io/github-2-9b-monthly-commits/)，高于 4 月份的 14 亿次。在周三的 GitHub Universe 大会上，该公司宣布现在每月有 74 亿次提交。从宏观角度来看，2024 年开发者向该平台推送的月提交量为 6500 万次。

这种增长是一个幸福的烦恼，但该公司的宕机已经变成了某种反复出现的主题。原因在于使用量的快速增长，正如该公司所说，这主要由“智能体需求”驱动。

## 增加 400 万个 CPU 核心

在 8 月份，GitHub CTO Vlad Fedorov 宣布该平台已经增加了 300 万个 CPU 核心（主要在 Azure 上）以支持这种增长。现在，GitHub 表示今年到目前为止已经增加了 400 万个 CPU 核心，外加 160 PB 的高速存储，以及为 GitHub Actions 提供了更多计算能力。

该公司还增加了 50 Tb/s 的网络容量，以保持所有这些数据的流动。

## 全新的 GitHub 架构即将到来

GitHub 还利用这一公告重申了其对重构平台以分离计算和存储的承诺。它在 [本月早些时候](https://github.blog/engineering/architecture-optimization/building-git-infrastructure-for-agent-scale-development/) 首次谈到了这一点。当时，该公司指出其内部基准测试表明，例如这种新架构可以提供高达 35 倍的更高写入吞吐量。

![](https://cdn.thenewstack.io/media/2026/10/32be13e4-6237ca0d-dc3d-42c3-8f06-e849405f9bbf-1024x768.jpg)

图片来源：The New Stack.

微软核心 AI 执行副总裁 Jay Parikh 在公告中写道：“智能体正在改变软件开发的体量和形态。增加容量很重要，但仅靠容量无法让我们到达目的地。我们还必须改变架构。”

在 2026 年，分离计算和存储并非什么激进的做法，但这表明 GitHub 过去一直在试图于遗留的基础上进行扩展。迁移到 Azure 及其服务基本上是唯一的选择，特别是当该公司自己的数据中心已经没有容量时。
