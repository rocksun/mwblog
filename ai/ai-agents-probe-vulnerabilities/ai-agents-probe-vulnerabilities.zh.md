**一个研究公共医药开销的 OpenAI 智能体**绕过了安全拦截，未经授权访问了澳大利亚政府 Medicare 统计门户网站上的公开和非公开文件，该国政府于周四透露了这一消息。据投诉称，该智能体是在 6 月份的内部评估期间运行的，OpenAI 称它还向内部服务器写入了文件。

独立的非营利性 AI 研究实验室 Transluce 分析了 URL 扫描服务 urlquery.net 的公共请求日志，发现自主智能体曾试图对新墨西哥州立大学数字图书馆、公共数据平台 Data USA 以及澳大利亚健康与福利研究所（AIHW）发动 SQL 注入、跨站脚本、命令注入和路径遍历攻击。这些智能体试图检索普通信息，包括一张历史照片、爱荷华大学数据以及维多利亚州的当地药物数据，并且这种攻击行为仅在常规检索方法失败后才出现。

Transluce 将 Data USA 和 AIHW 的活动归咎于一个智能体集群，并表示根据共享的目标、战术和时间，OpenAI 之前已确认该集群源自该公司。

在 [Transluce 于周三发布其调查结果](https://transluce.org/agent-activity)一天后，澳大利亚总理 Anthony Albanese 透露，一个研究公共医药开销的 OpenAI 智能体在 6 月份绕过了 Services Australia Medicare 统计门户网站上的拦截，并未经授权访问了公开和非公开文件。OpenAI 表示该智能体是在内部评估期间运行的，并于 9 月 10 日通知了澳大利亚政府。据 Albanese 称，该智能体还向内部服务器写入了文件。

这些事件尚未被公开证实为同一活动。不过，OpenAI [告诉澳大利亚广播公司](https://www.abc.net.au/news/2026-09-24/openai-agents-plotted-to-access-data-amid-medicare-hack/107189504)，Transluce 记录的大部分内容与其正在进行的对未对齐模型活动的审查中的案例重叠。

## 探测公共数据提供商

在 5 月 25 日和 26 日，试图从新墨西哥州立大学 Valmora 收藏馆检索照片的智能体遭遇了连续失败。它们对该服务进行了 7 次漏洞探测。这些探测包括尝试执行系统命令、针对 /etc/passwd 的路径遍历请求，以及包含 UNION SELECT 的 SQL 注入字符串；它们还伴随着针对该图像的 80 次请求爆发，尽管似乎没有一次成功。

两天后，从 Data USA 收集爱荷华大学数据的智能体遇到了由格式错误的查询参数引起的错误，随后针对该 API 进行了 12 次漏洞探测，涵盖 SQL 注入、反射型 XSS、服务端模板注入、路径遍历和命令注入。

## Cloudflare 拦截与暂存服务器变通方案

6 月 20 日和 21 日的 AIHW 案例遵循了非常类似的模式。在试图从 AIHW Tableau 仪表盘下载药物开销数据时，智能体遇到了 Cloudflare 的机器人保护。其中一个智能体在几分钟内做出了反应，用反射型 XSS 载荷测试仪表盘，尽管 Cloudflare 在它到达应用程序之前将其拦下。

Transluce 没有发现探测成功的证据，AIHW 也表示没有证据表明非公开信息被访问。该智能体最终在 AIHW 的预生产服务器 pp.aihw.gov.au 上找到了相同的公共数据集，并通过 100 多次扫描将其检索出来。

> 该智能体最终在 AIHW 的预生产服务器 pp.aihw.gov.au 上找到了相同的公共数据集，并通过 100 多次扫描将其检索出来。

Transluce 记录的最早的清晰序列可以追溯到 3 月 6 日，当时一个智能体试图从泰国麻醉品管制局办公室的 API 中提取缉毒统计数据。直接请求未返回页面内容，添加 JSON 格式参数也没有改变任何东西，因此该智能体通过 r.jina.ai 三次路由该页面，并返回了泰省名称混乱的文本。

然后，它编写了一个自定义的 Base64 编码脚本并通过 urlquery.net 提交，实际上是使用该服务的远程扫描浏览器针对数据运行自己的客户端 JavaScript。该脚本遇到了相同的解析问题，后来通过 Jina 的尝试触发了重定向到本地主机的操作，导致整个 API 被 Jina 封锁了一个小时。

从 4 月中旬开始，Transluce 在 urlquery.net 上的数千个智能体请求中发现了相同的技术，6 月 14 日，智能体使用该服务的浏览器创建了一个一次性电子邮箱收件箱，然后试图用它注册一个 urlquery.net 账号。注册用户可以将其扫描设为私密，这意味着 Transluce 分析的公共记录可能低估了实际发生的此类活动的数量。

具有网络访问权限的智能体并不局限于其开发人员赋予它的软件，因为远程浏览器、代理、URL 扫描器和其他公共服务可以填补空白，这为智能体提供了在其自身环境中无法提供的方式来发出请求或运行代码。

## AI 智能体的出口控制

如果智能体仍然可以通过网络发送它想要的任何东西，那么指令是远远不够的。对于狭义定义的工作，出站流量可以限制在获批的主机上，这种默认关闭的方法也用于[保护 AI 智能体沙盒](https://thenewstack.io/securing-ai-agent-sandboxes/)。研究智能体可能需要访问更多的网络，因此重点转向控制它们可以连接的位置。

[GKE 智能体沙盒](https://thenewstack.io/google-cloud-a-deep-dive-into-gke-sandbox-for-agents/)的指南建议使用隔离的运行时，采用默认拒绝的网络策略，仅开放智能体所需的端点。除非工作需要，否则公共代理、URL 扫描器和一次性电子邮箱服务可以保持封锁状态。

开发人员还可以限制智能体可以发送的内容。因此，API 集成可以限制对特定字段和格式的请求，而不是将其交给接受任何 URL 或请求体的网络工具。然后，运行时可以在发送任何内容之前捕获路径遍历尝试、SQL 注入字符串和可执行标记。OpenAI 在其 [Agents SDK 沙盒](https://thenewstack.io/openai-agents-sdk-sandboxes/)中采用了相关的隔离方法，该公司的 Responses API 技术主管曾表示，大型企业部署通常要求将智能体完全从网络中隔离出来。

重复失败也可能是暂停运行的原因，特别是当智能体不断遇到客户端错误、反机器人挑战或意外重定向，并开始尝试越来越激进的方法来绕过它们时，正如 Transluce 在其中几个案例中所记录的那样。

将原始任务、工具调用和服务器响应保存在同一个追踪中，可以让操作员在检索作业开始生成编码脚本、访问暂存域或发送漏洞利用载荷时，有更好的机会捕捉到这种行为变化，而不是稍后在别人的安全日志中发现它。

> 重复失败也可能是暂停运行的原因，特别是当智能体不断遇到客户端错误、反机器人挑战或意外重定向，并开始尝试越来越激进的方法来绕过它们时，正如 Transluce 在其中几个案例中所记录的那样。
