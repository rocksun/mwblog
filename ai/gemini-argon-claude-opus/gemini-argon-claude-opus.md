本文对 Google 的 Gemini 4 Argon 和 Anthropic 的 Claude Opus 5.5 进行了三项硬核任务的实测对比。测试发现，虽然 Argon 价格更低且在代码审查中表现平手，但在计费规范和长文本推理任务中暴露出明显的准确度和逻辑问题，作者认为目前尚无法盲目信任 Argon。

> 译自：[Gemini 4 Argon vs. Claude Opus 5.5: Half the price and about half as accurate](https://thenewstack.io/gemini-argon-claude-opus/)
> 
> 作者：Jessica Wachtel

**当谷歌宣布** [Gemini 4 Argon](https://thenewstack.io/google-gemini-4-argon/) 面向一小群测试人员发布时（9月30日），它附带了一张基准测试表，显示 Argon 在 18 项测试中的 14 项上超越了 [Claude Opus 5.5](https://thenewstack.io/claude-opus-5-5-release/)。其中包括 DeepSWE（77.9% 对 74.2%）以及 256K 到 100 万 Token 的 GraphWalks（84.2% 对 66.8%）。两周后的 10 月 13 日，谷歌向付费的 Gemini API 开发者开放了 Argon。

平心而论，谷歌也展示了 Opus 5.5 获胜的领域。Opus 在其他四个基准测试中处于领先地位，包括 Terminal-bench 4.0（66.4% 对 57.4%），该测试用于检验命令行中的智能体工作。

至少目前，谷歌在价格上也对 Anthropic 形成了压制。在 11 月 30 日之前，Argon 的价格为每百万输入 Token 2 美元，每百万输出 Token 10 美元，是 Opus 5.5 价格的一半。12 月 1 日，价格将分别上涨至 4 美元和 20 美元，与 Opus 持平。这给开发者大约六周的时间来决定 Argon 是更好，还是仅仅更便宜。

> 这给开发者大约六周的时间来决定 Argon 是更好，还是仅仅更便宜。

基准测试并不总能反映实际工作，而且半价窗口期只有在模型质量能与竞争对手匹敌时才有意义。为了看看 Argon 到底更好还是（目前）只是更便宜，我挑选了谷歌宣称具有优势的三个类别中的三个困难任务，对这两个模型进行了正面交锋测试。

## 测试

我通过 OpenRouter 在谷歌和 Anthropic 自己的服务器上，以默认推理设置对每个模型运行了每项测试一次。一个脚本根据我在测试任何模型之前构建并验证的密钥对每个答案进行了评分。答案密钥增加了更多的评分领域，以帮助确保每个测试的质量和彻底性。

* **Bug 猎取（Bug hunt）** – 一个包含 3,500 行代码的 Python 库，其中植入了 14 个逻辑 Bug 和 5 个干扰项。每个模型对代码进行审查，然后修复它发现的问题。
* **计费规范（Billing spec）** – 一个订阅计费引擎的规范，通过关于夏令时、月末日期和舍入的 80 个隐藏测试进行评分。后续追加了两种货币和另外 20 个测试。
* **长上下文（Long context）** – 一个包含 400 个服务的伪造维基（Wiki），其中包含散落的依赖项，分为三种规模。每个模型回答了三个带有埋设陷阱的图谱问题。

### Bug 猎取

这是一个平局。两个模型都找出了全部 14 个 Bug，其中包括 4 个只有在跨 3 个或更多文件追踪值时才会显现的 Bug。两者都没有标记干扰项。在后续测试中，两者都修复了全部 14 个 Bug，且没有破坏任何 93 个现有测试。

Argon 更便宜。其审查成本平均每个找到的 Bug 为 1 美分，而 Opus 为 2.4 美分，这个平均值我是根据每次调用的总费用计算出来的，而不是按单个 Bug 测量的。由于 Argon 使用的 Token 更少，即使在 12 月 1 日恢复全价时，它依然会更便宜。

* 数据：
  + 审查
    - Argon 53,031 输入，3,964 输出，0.15 美元，43.0 秒。
    - Opus 64,572 输入，4,053 输出，0.34 美元，38.9 秒。
  + 修复
    - Argon 54,923 输入，24,292 输出，0.35 美元，186.6 秒。
    - Opus 66,465 输入，34,263 输出，0.95 美元，219.8 秒。

## 计费规范

这是两个模型的准确度开始出现分歧的地方。Opus 通过了全部 80 个隐藏测试，在货币追加测试后通过了全部 100 个。Argon 在 80 个测试中通过了 11 个，在 100 个测试中通过了 20 个。  
  
Argon 没能通过大部分测试并不是因为它的逻辑不好。而是因为它在早期犯了一个小错误。它的代码向 Python 的 `datetime.combine()` 传递了一个额外的参数，这会引发错误，而该模块的大部分内容都依赖于这个辅助函数。当我亲自纠正了那一行代码后，Argon 的得分达到了 80/80 和 100/100. 我保留了官方评分的得分，但在这个任务上我想解释发生了什么，而不仅仅是罗列分数。

总体而言，Argon 更便宜，但一旦低价期结束，Opus 和 Argon 之间的价格差异就会消失，不过 Argon 较低的 Token 使用量在这个测试中仍然会使它更便宜。

* 数据：
  + 构建
    - Argon 3,907 输入，3,727 输出，0.05 美元，54.1 秒。
    - Opus 5,236 输入，7,763 输出，0.18 美元，63.0 秒。
  + 后续
    - Argon 8,881 输入，4,673 输出，0.06 美元，41.5 秒。
    - Opus 11,807 输入，7,267 输出，0.19 美元，51.9 秒。

## 长上下文

每个供应商计算 Token 的方式不同。我的 500K 文档在 Argon 上为 549,483 个 Token，在 Opus 上为 784,087 个。我的 900K 文档在 Claude 的 Tokenizer 上达到了 140 万个 Token，因此 Anthropic 的 API 拒绝了它。我添加了第三个大约 600K Token 的文档，这是两个模型都能容纳的最大文档。

在它们运行的每一个规模下，两个模型都完美地回答了三个问题中的两个。分歧出现在“ blast radius（爆炸半径）”问题上，该问题要求列出当一个服务发生故障时所有会宕机的服务。答案是 33 个服务。

Opus 在 500K 时找出了全部 33 个，在 600K 时找出了 32 个，且没有错误条目。在 500K 时，Argon 答对 20 个，答错 8 个；在 600K 时，答对 19 个，答错 16 个；在 900K 时，答对 23 个，答错 2 个。在 600K 和 900K 时，它将维基恢复后的依赖项视为已移除。与计费 Bug 不同，这不是一个小失误。Argon 在所有规模下的推理都是错误的。这是一个巨大的危险信号。

> 与计费 Bug 不同，这不是一个小失误。Argon 在整个答案中的推理都是错误的。这是一个巨大的危险信号。

我注意到的另一件事是，Argon 飞快地完成了这个长上下文测试。Argon 回答得很迅速，没有展示任何逐步思考的过程，而 Opus 花费了更多时间，因为它首先进行了推理。这反映在 Token 的使用上。Opus 使用了超过 5,000 个 Token（大部分用于推理），而 Argon 仅使用了 243-425 个。这可能与 Argon 的错误答案有关，尽管我无法从单次运行中证明其因果关系。

Argon 在这里更便宜，但在类似的任务上不值得使用它，因为它在很大程度上既不准确又很马虎。

* 数据：
  + 500k
    - Argon 549,483 输入，264 输出，1.10 美元，24.2 秒。
    - Opus 784,087 输入，5,532 输出，3.25 美元，68.3 秒。
  + 600k
    - Argon 652,492 输入，425 输出，1.31 美元，32.4 秒。
    - Opus 935,332 输入，5,158 输出，3.84 美元，69.1 秒。
  + 900K
    - Argon 982,367 输入，243 输出，1.97 美元，41.5 秒。
    - Opus 未运行。

## 结果

|  |  |  |
| --- | --- | --- |
| **测试** | **[Gemini 4 Argon](https://thenewstack.io/google-gemini-4-argon/)** | **[Claude Opus 5.5](https://thenewstack.io/claude-opus-5-5-release/)** |
| Bug 猎取审查 | 14/14，0 个误报 | 14/14，0 个误报 |
| Bug 猎取修复 | 14/14，保留 93/93 个测试 | 14/14，保留 93/93 个测试 |
| 计费规范 | 11/80 | 80/80 |
| 计费后续 | 20/100 | 100/100 |
| 爆炸半径，500K | 20/33，8 个错误 | 33/33 |
| 爆炸半径，600K | 19/33，16 个错误 | 32/33 |
| 爆炸半径，900K | 23/33，2 个错误 | 被拒绝，超过 100 万 Token |
| 总输入/输出 Token | 2,305,084 / 37,588 | 1,867,499 / 64,036 |
| 总费用 | 4.98 美元 | 8.75 美元 |
| 总时间 | 423.3 秒 | 511.0 秒 |

我的结果与谷歌的基准测试不符。Argon 在代码审查和修复方面与 Opus 打成平手，但成本不到其一半。它因为一行错误的代码输掉了规范测试，并且在每个长上下文爆炸半径问题上都漏掉了服务或凭空捏造了服务。

## 我是怎么想的？

基于这些测试，我不会使用 Argon。是的，它更便宜，在 Bug 猎取上与 Opus 准确度相当，但在其他测试中使用过它之后，对于任何任务我都不会盲目信任 Argon。

> 对于任何任务我都不会盲目信任 Argon。

Opus 5.5 是 Anthropic 的领先模型之一，Artificial Analysis 的独立指数将其排在 58 位，领先于 Argon 的 53 位。

虽然谷歌正在努力迎头赶上，但它目前还没有做到。
