**DeepSeek，这家自诞生起就在价格上不断挤压 OpenAI 和 Anthropic 的中国 AI 实验室**，最近更新了 V4-Flash 模型，并将其正式移出预览阶段。DeepSeek [文档](https://api-docs.deepseek.com/updates/)承诺，这个更新后的 Flash 模型在代码和智能体基准测试中超越了 V4-Pro 的预览版。

但其价格使得这一说法显得有些奇怪。V4-Flash 的价格为每百万输入 token 0.14 美元，每百万输出 token 0.28 美元。而 V4-Pro 的价格则分别为 0.435 美元和 0.87 美元。这意味着两者的价格几乎完全是三倍的关系。

如果[这款预算型模型在价格仅为三分之一的情况下击败了旗舰模型](https://thenewstack.io/deepseek-v4-flash-open-weights/)，那么旗舰模型存在的意义是什么？我必须找出真相，所以我给两个模型布置了相同的三个专业编程任务，并追踪了每一个 token。

## 测试过程

我使用了来自 Textualize 的 Python 终端格式化库 `rich`。我选择它是通过因为它是一个真实的生产级 Python 库，拥有[庞大的安装基础](https://pypistats.org/packages/rich)，并且具备足够的内部复杂度（样式跨度、渲染管道、单元宽度计算），足以让模型进行处理。

两个模型都在 [OpenCode](https://thenewstack.io/anthropic-claudecode-opencode-split/) 中运行——这是一款开源的终端编码智能体，类似于 Claude Code，但你可以插入任何模型。一个设置提示：OpenCode 内置的 DeepSeek 列表仅提供 Flash，并且有一个关于此问题的[已关闭且不计划修复的 GitHub issue](https://github.com/anomalyco/opencode/issues/30177)。为了将 Pro 加入模型选择器，我不得不向项目文件夹添加了一个小的配置文件（[本指南](https://haimaker.ai/blog/deepseek-opencode-setup/)中有 JSON 代码）。只花了两分钟，在这里提一下，以防你尝试在 OpenCode 上测试 Pro 时找不到模型。

我为每个模型建立了仓库的独立克隆，为每次测试启动了一个全新的会话，并使用了完全相同的提示词，因此模型是唯一的变量。以下是我运行的三个测试（按此顺序）：

* 一个 bug 修复
* 一个功能构建
* 一个性能优化（用于测试推理能力）

对于每一个测试，我都从 OpenCode 的会话计时器中记录了时间，以及从 DeepSeek 使用情况仪表板中记录了 token、API 请求次数和成本。

## 测试 1：Bug 修复

**提示词：** *用户报告称在 macOS 上导入 Rich 会导致崩溃。环境：Rich 15.0.0，Python 3.14，Apple Silicon 芯片的 macOS，VS Code 集成终端且工作目录在 Dropbox File Provider 文件夹内。[回溯信息] 仅使用绝对路径的命令在终端中可以正常工作。导入本身失败，因此 python -m rich.diagnose 无法运行。找出此代码库中的根本原因，修复它，添加回归测试，并运行测试套件。解释原因和你的修复方案。*

这个 bug 是真实存在的，且以一种安静的方式恶化。Rich 在导入时调用 `os.getcwd()`，仅针对 `FileNotFoundError` 进行了防御，但 macOS 的 File Provider 文件夹（Dropbox, iCloud）导致 `getcwd()` 抛出 `PermissionError`，因此整个库在运行一行用户代码之前就崩溃了。

两个模型都找到了相同的根本原因，并写出了相同的一行修复代码，将异常处理器范围扩大到了 `OSError`。两者都编写了一个模拟该故障的回归测试，并最终都通过了所有 957 项测试。我自己通过在每个打过补丁的副本上模拟阻塞的 `getcwd()` 来确认了修复效果。

修复方案是完全一样的。唯一的区别在于模型将测试放在了哪里。Pro 首先读取了仓库现有的测试文件，并将回归测试添加到了现有套件中，符合项目的规范。Flash 则创建了一个全新的测试文件。两者都可行，但 Pro 的做法是维护者在评审时所期望的。Flash 的做法则是一个赶时间的贡献者会提交的方式。

Flash 在 59 秒内完成了测试，使用了 6 次 API 请求和 119.9K token，成本不到一美分。Pro 用了 1 分 1 秒，13 次请求，159.2K token，成本约为一美分。修复方案相同，但 Pro 为此进行了两倍的 API 调用。我将此测试判定为平局。

## 测试 2：功能构建

**提示词：** *Rich 的 Text 类有一个 rstrip() 方法，可以在保留样式的情况下删除尾随空格。添加一个匹配的 lstrip() 方法来删除前导空格，以及一个 strip() 方法来同时处理两者。要求：1. 匹配 Text 类现有的代码风格 2. 正确保留剩余字符上的样式 3. 添加涵盖纯文本、带样式文本以及全为空格的文本的测试 4. 运行测试套件并确认一切通过 5. 解释你的实现决策*

在 Rich 中，文本可以带有格式，因此第 4 到第 9 个字符可能是加粗的。任务是添加一个从文本前面修剪空白的方法。修剪末尾很容易，因为内容不会移动。修剪前面则更难，因为每个字符都会滑动，而格式是固定在位置而不是字符上的。如果位置没有随之滑动，加粗就会落在错误的字母上。

两个模型都做对了。我通过八个边缘案例（部分跨度、全为空格的文本、无操作输入）对这两个实现进行了测试，两者都通过了。

有趣的是观察过程。Pro 将其初始代码库探索委托给了一个子智能体，该子智能体独立进行了 13 次工具调用，然后写出了一个第一稿中存在真实 bug 的实现。它丢弃了在修剪后的空白区域内开始的样式跨度。它自己的测试捕获到了这个问题，并在一次迭代中修复了它。这就是系统按预期工作的结果，但这也带来了更多的开销。Flash 只是读取了文件并编写了代码。

Flash 在 1 分 29 秒内完成，使用了 6 次请求和 191.2K token，再次花费不到一美分。Pro 用了 1 分 43 秒，23 次请求，333.6K token，花费约为两美分。对于相同的功能，这几乎是四倍的 API 调用和 75% 更多的 token 使用量。

Flash 在本次测试中胜出，但仅基于效率。代码质量相同（都通过了八个边缘案例），但 Flash 速度更快，API 调用次数是其四分之一，token 使用量是一半，成本也是一半。代码平局，Flash 在效率上获胜。

## 测试 3：性能优化

**提示词：** *维护者希望大型表格的渲染速度更快。写一个小型的基准脚本，测量将包含 5,000 行和 6 列的表格渲染为字符串 Console 的过程。记录基准时间，进行性能分析以找到主要的瓶颈路径，并在不改变任何公共行为或输出的情况下优化该路径。展示基准测试中的前后时间对比，解释你更改的内容以及为何速度更快，并运行完整的测试套件以证明没有破坏功能。*

前两个测试都有明确的正确答案。而这个任务是开放式的。正是这种开放式任务，使得两个模型不再具备可替代性。

Flash 表现得非常激进。它工作了 27 分钟，发出了 128 次 API 请求，消耗了 1540 万个 token，总共花费约 8 美分。它不仅加快了代码速度，还构建了自己的测试套件，在 37 种表格中对比了新旧输出，在此过程中捕获并修复了自己产生的一个 bug，两次注意到它的基准测试意外地测量了库的错误副本，并清理了 13 个类型检查错误。Flash 声称其版本速度提升了 1.84 倍。我亲自测量后得到了 1.83 倍，因此判定为准确。

Flash 还声称其新输出在字节级别上与旧输出完全相同，但我发现有一个例外情况。在彩色终端上的某种特定表格设置中，不可见的颜色代码书写顺序略有不同。在屏幕上，两个输出看起来完全一样，任何用户都不会注意到。但“完全相同”的陈述是错误的。这很有趣，因为 Flash 在这里完成了本次实验中最好的工程工作，但随后描述其工作时比实际情况更严谨，而它本不需要这样做。

> Flash 在这里完成了本次实验中最好的工程工作，随后描述其工作时比实际情况更严谨，而它本不需要这样做。

Pro 将同一个提示词当作代码审查来处理。它工作了 15 分 21 秒，进行了 57 次请求和 470 万个 token，成本约为 7 美分。它在绘图代码中发现了一个步骤正在执行重复工作，将其删除了，收紧了一段繁忙的代码，并报告了 3.3% 的性能提升。我测量结果为 1.06 倍，而且其输出确实与原始输出在字节级别上完全相同。

它甚至正确处理了 Flash 处理错误的那一种情况。Pro 关于其工作的每一句话都是真实的。只是它的工作量没那么多。Flash 发现的巨大加速存在于 Pro 观察的相同测量数据中，但 Pro 错过了它。

> 便宜的模型在这次任务中表现出了创造力，而昂贵的模型则让工作流于表面。

简单来说：便宜的模型在这次任务中表现出了创造力，而昂贵的模型则让工作流于表面。

在这个测试中，数据变得有趣起来。Flash 27 分钟的运行消耗了 1540 万个 token，成本约 8 美分，因为 98.6% 的 token 是按每百万四分之一美分计费的缓存读取。Pro 的运行使用了不到三分之一的 token，但成本依然约为 7 美分，因为 Pro 的费率是 Flash 的三倍。Flash 的一千五百万个 token 听起来很昂贵，但实际上只转化为 8 美分。
