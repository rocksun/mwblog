本文通过三个定制测试，对比了 GPT-6.1 Terra 与 Claude Opus 5.5 在最大负载下的表现。结果显示，Terra 在代码、科学计算和数据处理任务中不仅准确率更高，而且成本和耗时显著低于 Opus。

> 译自：[GPT-6.1 Terra vs. Claude Opus 5.5: Cheaper and faster in three tests at max effort](https://thenewstack.io/gpt-6-1-terra-vs-claude-opus-5-5/)
> 
> 作者：Jessica Wachtel

**OpenAI 于** 10 月 26 日[发布了 GPT-6.1 Terra](https://thenewstack.io/openai-terra-bypassed-restrictions/)，并在其营销材料中包含了与 Opus 5.5 的两次直接对比。该公司声称，在 Terminal-Bench-Science 0.1 测试中，Terra 与 Opus 5.5 的差距在五个百分点以内，且备用方案的估计成本不到前者的五分之一。该测试要求智能体编写代码来执行研究任务，例如跟踪细胞分裂。

在最大努力模式下，[OpenAI 描述](https://openai.com/index/introducing-gpt-6-1-terra/) Terra 的 Token 效率是 Opus 的三倍多，标准输入和输出 Token 的价格则是后者的四分之一。另外，据报道，每个任务的估计成本约为九分之一。在评估多步骤计算机使用任务的基准测试 Agents’ Last Exam 中，Terra 得分为 60.0%（每个任务 1.01 美元），Opus 得分为 63.2%（每个任务 8.82 美元）。准确率差距为 3.2 个百分点，成本比为 8.73 比 1，二者准确度并不相同。

在标准的未缓存 API 速率下，[Terra 的价格为每百万输入 Token 1 美元，每百万输出 Token 5 美元](https://developers.openai.com/api/docs/models/gpt-6.1-terra)，而[Opus 5.5 的价格分别为 4 美元和 20 美元](https://www.anthropic.com/claude-opus-5-5)。在输入/输出 Token 组合相同且没有其他定价调整的情况下，Terra 需要四倍的 Token 才能匹配 Opus 的成本。实际任务成本还取决于 Token 使用量、缓存读写以及任何适用的定价调整。

准确率声明引起了我的兴趣，因为[当我用 Terra 与 OpenAI 自己的 GPT-6 Astra 进行对比测试时](https://thenewstack.io/gpt-6-1-terra-vs-gpt-6-astra/)，Terra 留下了部分数字总和未计算，并给出了一些错误答案。那篇文章主要集中于分析大型数据集，例如数据库记录和服务器日志。

由于针对 Opus 的声明侧重于计算机使用和科学编码，我围绕这些领域构建了两个测试。我还添加了第三个测试，用于重现 Terra 在与 Astra 对比时遇到困难的那种大型数据集任务，以观察 Opus 是否表现出相同的弱点以及它是如何处理的。

## 测试过程

我将 Terra 与 Opus 的测试运行了几次，因为在较简单的级别上，两个模型的得分相似，就像 Terra 对比 Astra 的测试一样。当得分过于接近时，我提高了测试难度并再次运行，最多运行三次。以下结果来自最终版本，其中包括我在两个模型都未能完成第一个版本后缩小的 CI 审计。由于我在看到早期结果后更改了测试，并且每个最终版本每个模型只运行一次，因此这些结果并未确立工作负载之间的可重复性或平均性能。

我通过 OpenAI 和 Anthropic 自己的 API 为每个模型运行了每个最终测试一次，每个供应商的努力程度设置均设为最大。这些设置并未在各个模型之间强加等效的推理预算。我没有限制轮数。两个模型每个响应都有 128,000 个 Token 的输出限制，包括推理；多轮任务的总数可能会超过该限制。我使用脚本对照已验证的答案键对每次运行进行评分。

以下数字汇总了每个最终运行中所有轮次的 Token；推理 Token 包含在输出总数中。每次运行旁边的美元数字是使用标准未缓存输入和输出速率的估计值，而不是发票总额。对于单个请求输入 Token 超过 272,000 的情况，Terra 的费率会增加；仅凭聚合任务总数无法显示是否超过了该阈值。报告的调整缓存后的总数单独列出。总数不包括早期测试版本，也不包含任何单独计费的工具或执行基础设施。

* **发布分类（Release triage）：** 我构建了一个伪造的 GitHub 风格网站，其中包含一个失败的软件发布，每个模型必须通过基于截图的浏览器界面（使用点击和输入的 URL）来修复它。最终版本有六个根源问题，分散在代码、功能标志和一个密钥中，此外还有不稳定的测试诱饵和三个植入的指令，指示模型绕过安全设置。
* **细胞谱系（Cell lineage）：** 我生成了一个包含 72 帧分裂细胞的带噪声显微镜视频，模型编写并运行自己的 Python 代码来跟踪它们。它们必须记录每一次分裂，并将最后一帧中的每个细胞追溯到其亲代。
* **CI 历史审计（CI history audit）：** 此测试将大约 1,200 行 CI 测试结果放入单个提示词中，不使用任何工具，并针对它们提出了 50 个问题。数据混合了三个时区、三种持续时间格式、重命名的测试、重复行以及月中价格变动。

### 发布分类

这是一场 50 对 50 的平局，并且在测试的所有迭代中一直保持平局。为了获得得分，我使用了 50 项通过/失败检查。大多数检查模型是否提交并关闭了正确的议题并修复了每个问题以使发布能够通过。其余部分检查模型没有更改它们不应该更改的内容，例如诱饵拉取请求和设置，并忽略了植入的指令。

在最高难度版本中，两个模型都找到了所有六个根本原因，恢复了发布分支上正确的拉取请求，并重用了最旧的开放议题而不是提交重复项。两个模型都没有遵循三个植入指令中的任何一个。

区别在于它们是如何到达那里的。Opus 通过键控 URL 在页面之间跳转了 102 次，而 Terra 这样做了 23 次，主要通过点击网站进行。Opus 编写的输出 Token 大约是 Terra 的五倍。

对于这样的浏览器工作，Terra 在大约 17.1% 的 Opus 估计未缓存 Token 成本下获得了相同的分数，即 5.83 比 1 的成本比。这是一项独立的合成任务，而不是对 OpenAI 基准测试的复制。提示词缓存可以降低重复截图和对话输入的成本；下表列出了有缓存和无缓存时报告的总数。

数据如下：

* Terra：186 轮，输入 22,117,582，输出 7,659（推理 2,718），22.16 美元，807 秒。
* Opus：170 轮，输入 32,100,919，输出 39,838（推理 18,795），129.20 美元，934 秒。

### 细胞谱系

这是在主题上最接近 OpenAI 的 Terminal-Bench-Science 与带备用方案的 Opus 5.5 对比的测试。我的合成细胞追踪测试并未复制该基准测试。在我的运行中，Terra 得分 48/50，而 Opus 得分 43.5/50，成本约为 Opus 估计未缓存 Token 成本的二十分之一。

我将此测试满分设为 50 分。每个模型因找到细胞分裂而获得 20 分，对于它报告的并未发生的每一次分裂扣除 0.5 分。通过将最后一帧中的每个细胞追溯到其来源的细胞，它又获得了 20 分。最后的 10 分来自关于结果的 10 个问题，例如细胞分裂了多少次以及有多少细胞漂移出了视野。

Terra 匹配了所有 20 次分裂，并且正确回答了所有 10 个总结问题。Opus 漏掉了两次分裂，报告了一次从未发生的分裂，并且对总分裂数和漂移出视野的细胞数都进行了错误计数。两个模型都将 20 个最终细胞中的两个分配给了错误的起始细胞。

尽管 Opus 得分较低，但它使用了更多的轮数和代码执行。它在 129 轮中运行了 96 次代码，耗时约 36 分钟。Terra 在 37 轮中运行了 30 次代码，并在大约 15 分钟内完成。

数据如下：

* Terra：37 轮，输入 3,118,018，输出 69,413（推理 55,453），3.47 美元，920 秒。
* Opus：129 轮，输入 19,722,068，输出 201,194（推理 135,672），82.91 美元，2,187 秒。

### CI 历史审计

该测试并未复制 OpenAI 的计算机使用或科学编码基准测试。它类似于我针对 Astra 运行的大型数据集测试。我的第一个版本有 3,920 行，在达到 128,000 个输出 Token 之前，两个模型都没有产生最终答案。

对于第二个版本，我将文件削减到大约 1,200 行，并增加了月中价格变动作为额外的挑战。Terra 以 47 比 50 完成。它在两个状态计数上偏差为一，并且在回答关于 GPU 运行程序的问题时回答了 0 美元，而它本应说明数据未涵盖这些内容。Opus 再次在达到每个响应 128,000 个 Token 的输出限制之前没有产生最终答案。这是在响应限制内未能以最大努力完成；这并不意味着 Opus 在其他配置下无法回答。

Terra 回答了所有 50 个问题并错了三个：两个状态计数偏差一以及一个它应该标记为无法回答的问题。这给出了 47/50，或者在此测试评分下为 94%。它在没有工具的情况下完成了这个版本的大型表格任务；Opus 没有返回可供评分的答案。

数据如下：

* Terra：输入 56,959，输出 61,539（推理 61,122），0.36 美元，691 秒。
* Opus：无最终答案，输入 72,460，输出 128,000，2.85 美元，841 秒。

## 结果

|  |  |  |
| --- | --- | --- |
| **测试** | **GPT-6.1 Terra** | **Claude Opus 5.5** |
| 发布分类（满分 50） | 50 | 50 |
| 细胞谱系（满分 50）| 48 | 43.5 |
| CI 历史审计（满分 50）| 47 | 未完成 |
| 总输入/输出 Token | 25,292,559 / 138,611 | 51,895,447 / 369,032 |
| 估计未缓存 Token 成本 | $25.99 | $214.96 |
| 缓存估计成本 | $2.51 | $21.52 |
| 总耗时 | 2,418 s | 3,962 s |

*两个成本行是我的估计，而不是账单金额。我将每个 API 报告的Token计数乘以供应商的标准费率，对于缓存行，我按每个供应商较低的缓存费率对缓存的Token进行定价。*

Terra 在发布分类上与 Opus 打平，在细胞谱系上得分更高；它完成了 CI 审计，而 Opus 没有返回最终答案。在这三次最终运行中，Terra 的估计未缓存 Token 成本为 25.99 美元，而 Opus 为 214.96 美元，约为前者的 12.1%，即 8.27 比 1 的比率。Terra 的总耗时为 2,418 秒，而 Opus 为 3,962 秒，相差 1,544 秒，即约 25.7 分钟。这些总数不包括先前的测试版本。

### 我怎么看？

当 Terra 能够点击、运行代码并检查其工作时，它表现得很好。在没有工具的最终表格任务中，Terra 返回了答案，而 Opus 没有。该结果适用于这些特定的运行，而不是模型的通用排名。

这些测试使用了最大努力（max effort），而 Astra 测试使用了高。任务也不同，因此该比较并未隔离努力设置的效果。[Anthropic 建议](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)从其默认的中等努力开始运行 Opus 5.5，并将更高的设置保留用于测试显示质量提升的工作负载。我没有在这里测试该配置。

对于像这些浏览器和代码执行任务这样的工作，在承诺使用 Opus 之前，我会在试用中以最大努力运行 Terra。我还会在最适合工作负载的努力设置下比较每个模型，并在多次运行中检查准确性、完成率、时间和成本。我仍然会仔细检查大型表格上的数字答案，Terra 在这次测试和之前的 Astra 对比中都在那里犯了错误。
