**OpenAI 于周四推出了 Agents API** 公测版，为那些希望运行数天无人值守代理的开发者开放了 Codex 后端的接口。

现在，开发者无需自行构建系统来维持代理的运行，因为该 API 会在作业进行时进行跟踪，并为代理提供执行任务的场所，即使任务的持续时间远超单个上下文窗口的限制。

这使得长期运行的代理更容易进行试验，但也给开发者提供了更多消耗算力的途径。有趣的是，就在 Agents API 发布当天，由于对 GPT-6 Astra 的需求导致产能紧张，OpenAI 暂停了每月 200 美元的 Pro 订阅计划的新注册。

Codex 工程负责人 [Thibault Sottiaux](https://www.linkedin.com/in/thibault-sottiaux-27195366/) 在 X 上写道，Pro 订阅“给我们的系统带来了最大的压力”，并补充说 OpenAI 正在“尽可能快地”增加产能。

Agents API 和 ChatGPT Pro 是独立的产品，因此没有理由认为其中一个占用了另一个的资源。尽管如此，时间点的选择依然引人注目：该公司一方面在让开发者更轻松地运行数小时甚至数天的代理，另一方面却在[缩减对其高负载消费者计划的访问权限](https://x.com/thsottiaux/status/2098113585683808624)，并努力增加更多产能。

## 代理推理带来的算力快速累积

随着任务时间的延长，API 可以压缩早期上下文，因此代理不会在达到模型上下文限制时停止工作。它还可以在需要时引入工具，或将大型作业的部分任务分发给并行工作的子代理。实际工作可以在 OpenAI 的沙箱中运行，也可以在开发者控制的基础设施上运行。

> 实际工作可以在 OpenAI 的沙箱中运行，也可以在开发者控制的基础设施上运行。

随着代理的进展，它们会回到模型进行下一步操作，一个耗时数小时的作业所产生的推理成本远高于普通的 API 调用。当代理并行工作时，使用量增长得更快。

OpenAI 已经在内部目睹了这种情况。在 [9 月 6 日发布的一份研究报告](https://openai.com/index/research-acceleration-view-inside-openai/)中，OpenAI 表示，截至 8 月中旬，其研究机构每经历一个人类工作日，就会记录 3.1 个代理工作日（按标准的八小时工作制衡量）。按代理使用量排名，处于中位数的员工每天在推理上的花费超过 600 美元，而[第 90 百分位的员工每天花费超过 7,000 美元](https://thenewstack.io/openai-agent-research-bottleneck/)。

在 6 月之前，OpenAI 研究人员的工作时间还多于其代理，但到了 8 月中旬，代理的工作量已经是他们的三倍。

可以说，OpenAI 的研究人员是一个极端案例，但这些数字展示了当代理使用规模化时会发生什么。一个人突然可以生成远超其人力所能及的推理量。

> 一个人突然可以生成远超其人力所能及的推理量。

## 摩擦力限制了算力需求

Agents API 通过将编排层排除在账单之外，降低了这种实验的成本。开发者只需为代理实际使用的模型、工具和托管计算资源付费。

其反面是，现在消耗更多推理资源变得更容易了。上下文压缩就是一个很好的例子。过去，完整的上下文窗口迫使开发者决定丢弃什么，或者如何总结目前的工作。现在 API 会自动处理这些，代理可以继续运行。这对开发者很有用，但也意味着当上下文窗口填满时，工作负载并不会停止。

## Astra 的需求触及了上限

Astra 的推出提供了未来可能情况的预览。OpenAI 在[该模型于 9 月 3 日推出](https://thenewstack.io/gpt6-astra-developer-access-delayed/)不到两周后就停止接受新的 Pro 订阅者，称这些账户对其系统造成了最大的压力。Agents API 有其自身的速率限制和使用层级，因此 Pro 订阅的暂停不会直接影响使用该 API 的开发者。尽管如此，该公司已经不得不围绕其最新模型进行产能管理。

## 基础设施的重要性现已超过基准测试

开发者运行的代理越多，运行时间越长，使用量的增长就越快。一名开发者可能同时运行多个代理，每个代理在任务执行过程中都会反复调用模型。因此，仅凭人力数量并不能说明你消耗了多少计算资源。

对于长期运行的代理，挑战在于在不浪费 Token 或丢失任务跟踪的情况下保持工作推进。[Cloudflare 今年夏天也做出了类似的判断](https://thenewstack.io/cloudflare-ai-web-economics/)，认为围绕 AI 工作负载的基础设施最终将与模型本身同等重要。

> 对于长期运行的代理，挑战在于在不浪费 Token 或丢失任务跟踪的情况下保持工作推进。
